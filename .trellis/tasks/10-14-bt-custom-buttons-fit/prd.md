# 蓝牙自定义报文区修复：按钮区随可用空间自动 + 编辑工具栏常驻

## Goal

1.23.82 的「封顶 3 行 + 内部滚动」上线后，现场反馈两个问题（用户截图 + 描述）：

| # | 现象 | 期望 |
|---|---|---|
| D1 | 把**日志栏往上拖、腾出空间之后**，按钮区**还是很窄并出现滚动条**（10 个按钮只显示 3 行） | 腾出的空间应当被按钮区用上：**空间够就把按钮全显示出来**，只有空间真不够时才滚动 |
| D2 | 最底下的编辑按钮（新增…/批量新增…/导出…/导入…/全部清除）**跟着按钮一起被折叠进去** | 编辑按钮应**一直保持在底部**（常驻可见），不随折叠隐藏 |

用户已确认的修法（本轮问答）：

- 任务：建立 Trellis 任务并推进。
- 高度策略：**按内容自动**（不再固定 3 行；空间够就不滚动，不够才滚动；默认分栏仍保日志）。
- 工具栏：**移到折叠区外面，常驻在按钮区下方**。

## 现状证据（1.23.82 的实现）

- `_custom_scroll_cap()` 返回「3 行按钮高度」，`_apply_custom_scroll_cap()` 把它设成
  `QScrollArea.maximumHeight` ⇒ **硬封顶**：只要按钮超过 3 行就滚动，与分栏给了多少空间无关
  （实测：分栏 `[200,600]`、10 个按钮 → 滚动区仍 76px + 滚动条）。
- 工具栏行（5 个按钮 + 提示）加在 `CollapsibleSection.content_layout()` 里 ⇒ 与按钮网格同属折叠内容
  ⇒ 收起时一并消失。

## Requirements

### R1 按钮区高度按内容自动（D1）

- R1.1 滚动区的高度**上限 = 内容需要的高度**（`custom_host.sizeHint().height()`，即按钮全部显示所需高度），
  **不再是固定 3 行**；高度**下限 = 1 行按钮高度**（防止被分栏压成 0，也替代原来「封顶」在默认分栏下
  保住日志的作用）。
- R1.2 于是行为为：空间 ≥ 内容高度 → **不出现滚动条**，按钮全显示；空间 < 内容高度 → 出现滚动条
  （分栏给多少用多少）。
- R1.3 默认分栏（`RIGHT_SPLIT_DEFAULT = [420, 240]`）下**日志仍不被挤**：靠「分栏默认尺寸 + 滚动区最小高度」
  保证，而不是靠硬封顶（`test` 断言日志高度下限）。
- R1.4 按钮重建后与主题/字号变化后都要重算上下限（沿用 1.23.82 的两个调用点）。

### R2 编辑工具栏常驻（D2）

- R2.1 5 个编辑按钮 + 提示行**移到折叠区外面**（仍紧贴按钮区下方），折叠/展开都可见。
- R2.2 折叠只收起**按钮网格**（内容区只剩滚动区）。
- R2.3 更新 `core`：`CUSTOM_ROWS_MAX` 不再使用（封顶概念取消）→ 改为
  `CUSTOM_MIN_ROWS = 1`（滚动区最少可见行数，单一来源）。

### R3 测试

- R3.1 `test_bluetooth_widget.py` [14] 重写为：
  - **10 个按钮 + 分栏给足空间（`[200,600]`）→ 无滚动条**（`verticalScrollBar().maximum() == 0`）
    且滚动区高度 ≥ 内容高度 − 2（用户报障场景，**这条正是 D1 的判据**）；
  - **64 个按钮 + 同样空间 → 仍有滚动条**（空间真不够时不该硬塞）；
  - 默认分栏 + 64 个按钮 → 日志高度 ≥ 120（D1 修好但日志仍不被挤）；
  - 上下限正确：`minimumHeight` ≈ 1 行、`maximumHeight` ≈ 内容高度；
  - **折叠后编辑按钮仍可见**（`is_content_hidden()` 为真时 `btn_custom_add.isVisible()` 仍为真）、
    且工具栏**不在**折叠内容里（`btn_custom_add` 不是 `custom_group.content` 的后代）；
  - 保留：按钮少不滚动、收起高度骤减、分栏尺寸采集与重启恢复。
- R3.2 `test_bluetooth_core.py` [13]：常量改为 `CUSTOM_MIN_ROWS`（旧 `CUSTOM_ROWS_MAX` 不再存在）。
- R3.3 五份蓝牙测试 + `release_check.py --with-gui` FAIL=0（既有环境红除外）。

## Acceptance Criteria

- A1 日志栏上拖腾出空间后：10 个按钮**全部显示、无滚动条**；按钮更多时按分栏给的高度显示、多余部分滚动。
- A2 折叠自定义区后，「新增…/批量新增…/导出…/导入…/全部清除」**仍然可见可点**。
- A3 默认分栏下（不动分栏器）64 个按钮时日志仍保有可用高度（≥120px）。
- A4 换字号/主题后上下限随之重算（不裁字、按钮不被压扁）。
- A5 既有行为不回退：按钮少时不滚动、分栏尺寸与折叠状态记忆、按钮绑定协议/地址的发送路径不变。

## 非目标

- 不改「分组/关键字筛选」「超量切下拉菜单」（仍未选）。
- 不改 `MAX_CUSTOM_BUTTONS`、按钮数据结构、发送/解析链路。
- 不改 Web 版。
