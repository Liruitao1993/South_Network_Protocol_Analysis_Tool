# 批量解析摘要：测试帧（业务标识 0xF0）体现测试模式

## Goal

批量解析结果摘要（协议9 新一代载波 / 协议10 国网新一代，协议11 复用 10）中，**测试帧**（应用层业务标识 `0xF0`，或协议10 的通信测试/检测扩展命令）必须在摘要里体现**测试模式**字段内容——即解析器产出的「测试模式/配置操作」及其子模式（安全测试模式/新一代测试模式），让现场人员不点开详情就能从摘要看出这是哪种测试。

## Confirmed Facts（代码证据）

- **测试帧解析**：协议9 `csg_new_gen_cmd_payloads._parse_cmd_test_frame`（`0xF0` → `测试ID`；`test_id==0x03` → `_parse_legacy_ext_cmd` 产出字段 **`测试模式/配置操作`**，模式名来自 `_LEGACY_TEST_MODE_MAP`，如 `3 = PLC物理层透传测试模式`，comment 形如 `"PLC物理层透传测试模式（高4位）"`；`test_id==0x04` → `扩展ID`，名称来自 `_TEST_EXT_ID_MAP`，如 `0x0001 Bitloading测试模式`）。
- **协议10 检测扩展命令**：`gw_new_gen_cmd_payloads._parse_comm_test_ext` 产出字段 **`测试模式/配置操作`**（模式名来自 `_EXT_TEST_MODES`），模式 13 → `安全测试模式`、模式 15 → `新一代测试模式`。
- **业务标识名称**：`csg_new_gen_parser.SERVICE_ID_MAP[0xF0] = "测试帧"`，解析表行为 `("业务标识", "0xF0", "240", "业务标识 240 - 测试帧", ...)`（`test/test_csg_batch_parse_level.py:201` 用真实抓包帧断言过）。
- **摘要生成点**：`main_gui._get_csg_new_gen_summary`（协议9，应用层分支调用 `main_gui._extract_csg_core_content`）、`main_gui._get_gw_new_gen_summary`（协议10/11）。两者当前都**没有**读取测试模式字段。
- **真实帧样例**（`test/test_csg_batch_parse_level.py:196` 的 TCP 包装帧，剥 15 字节 EDA5 头后）解析出：`业务标识 240 - 测试帧` + `测试ID 2 频段切换命令` + `测试数据区 通信频段: 0x02` —— 即**存在没有「测试模式/配置操作」字段的测试帧**（测试ID 0/1/2 类）。
- 测试宿主范式：`test/test_gw_monitor_summary.py` 用最小 `Host` 类挂 `MainWindow._get_*` 未绑定方法，免 GUI 驱动；协议9 摘要方法会调用 `self._extract_csg_core_content`，宿主需同时提供两者。

## Requirements

### R1 测试帧识别

- 协议9：`业务标识` 行解析值为 `240`（或 raw 含 `0xF0`、comment 含「测试帧」）→ 判定为测试帧。
- 协议10/11：不依赖业务标识，**按字段存在性判定**——出现 `测试模式/配置操作`（或 `安全测试模式`/`新一代测试模式`）即视为测试类报文。
- 上行测试帧（协议9 `上行负载` 行、无测试模式字段）→ 摘要体现「测试帧上行（确认/否认，无数据单元）」。

### R2 测试模式内容提取（纯逻辑，可脚本测试）

新增 `main_gui.MainWindow._extract_test_mode_content(table_data) -> str`（`@staticmethod`，不触碰 self，便于无 GUI 测试）：

| 解析表字段 | 摘要片段 |
|---|---|
| `测试模式/配置操作` | `测试模式:<模式名>(<模式号>)` |
| `安全测试模式`（模式13） | `安全测试模式:<名称>` |
| `新一代测试模式`（模式15） | `新一代测试模式:<子模式名>`（如 `CCO信标机制切换`） |
| 测试帧但无上述字段：`测试ID` | `测试ID:<名称>`（如 `测试ID:频段切换命令`、`测试ID:2.0测试`） |
| 测试帧但无上述字段：`扩展ID` | `扩展ID:<名称>`（如 `扩展ID:Bitloading表下发`） |
| `测试数据区` comment 含 `通信频段` | `通信频段:0x02`（便于频段切换类测试帧一眼看出频段） |
| 上行测试帧（`上行负载` 行 + 自证为测试帧） | `测试帧上行（确认/否认，无数据单元）` |
| 无任何测试模式痕迹 / 非测试帧 | 返回空串（调用方不加任何片段） |

- **名称/数值双槽探测（不做描述文本黑名单）**：两个解析器把名称放在**相反**的槽位——协议9 表61 `raw=0x03 parsed=3(数值) comment=PLC物理层透传测试模式（高4位）`；协议10 检测扩展命令 `raw=3 parsed=HPLC物理层透传测试模式 comment=检测扩展命令: …`。判定规则：**parsed 非数值时名称在 parsed，否则在 comment，再退回 raw**；数值取 parsed/raw 中的数值者。协议9 表61 恒定输出的占位子模式行（comment 含「仅测试模式13生效」）一律跳过。
- **括号去重**：名称自身已带括号（`保留(14)`、`转发应用层报文至应用层串口信道测试模式(暂未使用)`）时不再追加模式号，避免 `保留(14)(14)`。
- **测试帧自证**：helper 内的 `上行负载` 回退要求表中存在 `业务标识` 且为 `240`/`0xF0`/含「测试帧」——该行名被 4 个非测试上行业务共用（sid 0x01/0x03/0x04/0x06），不设条件会把这些帧写成「测试帧上行」。
- 多个片段用 ` | ` 连接；顺序：测试模式 → 安全/新一代子模式 → 测试ID/扩展ID → 通信频段；有 `测试模式/配置操作` 时不再输出 `测试ID`（避免冗长）。

### R3 接入摘要

- 协议9：`_extract_csg_core_content` **首个分支**处理测试帧（优先于 确认/否认、数据传输、命令帧分支——否则帧类型=命令帧的测试帧会走通用「命令帧」列表，丢测试模式）。
- 协议10/11：`_get_gw_new_gen_summary` 在既有片段之后追加；**仅当表中存在三个哨兵行之一**（`_TEST_MODE_SENTINELS` = 测试模式/配置操作 / 安全测试模式 / 新一代测试模式）时才调用 helper——协议10 无 0xF0 概念，无条件调用会依赖「上游不发同名字段」的隐式契约。
- 摘要保持既有分隔风格 ` | `，不改变其它帧类型的输出。

### R4 测试与门槛

- `test/test_csg_summary.py`：**去掉文件内复刻的摘要逻辑**，改为复用 `main_gui.MainWindow` 未绑定方法（与 `test_gw_monitor_summary.py` 同范式），并新增**整帧→摘要**用例（不经 helper 直调，覆盖 gate 与分支接线）：
  - 真实抓包 0xF0 帧（TCP EDA5 剥 15 字节）→ 含 `业务标识:测试帧(0xF0)` 与 `测试ID:频段切换命令` + `通信频段:0x02`；
  - 1.0 测试帧整帧（测试ID=0x03 + 表61 模式 3）→ 含 `测试模式:PLC物理层透传测试模式(3)`，且不含 `测试ID:`；
  - 2.0 测试帧整帧（Bitloading表下发）→ 含 `测试ID:2.0测试` + `扩展ID:Bitloading表下发`；
  - 上行测试帧整帧 → 含 `测试帧上行（确认/否认，无数据单元）`；
  - **非测试上行业务帧回归网**：sid 0x01/0x03/0x04/0x06 上行整帧 → helper 返回空、摘要不含「测试帧/测试ID」。
- `test/test_gw_monitor_summary.py`：新增检测扩展命令用例——模式 3（`测试模式:HPLC物理层透传测试模式(3)`）、模式 13（+`安全测试模式:SM3算法测试`）、模式 15/子 6（`新一代测试模式:CCO信标机制切换`）、模式 1（名称自带括号不重复）、模式 0（普通通信测试无片段）。
- `release_check.py` 既有清单不变（两个测试均已在 CORE_TESTS 内）。

## Acceptance Criteria

1. 协议9 测试帧（真实抓包帧）摘要包含 `业务标识:测试帧(0xF0)` 与 `测试ID:频段切换命令` + `通信频段:0x02`。
2. 协议9 1.0 测试帧整帧摘要包含 `测试模式:PLC物理层透传测试模式(3)`（且不重复输出 `测试ID`）；2.0 测试帧整帧摘要包含 `测试ID:2.0测试` + `扩展ID:Bitloading表下发`。
3. 协议9 上行测试帧整帧摘要包含 `测试帧上行（确认/否认，无数据单元）`。
4. 协议10 检测扩展命令摘要：模式 3 → `测试模式:HPLC物理层透传测试模式(3)`；模式 13 → 另含 `安全测试模式:SM3算法测试`；模式 15/子 6 → `新一代测试模式:CCO信标机制切换`；模式 1（名称自带括号）不重复括号；模式 0 → 无片段。
5. 非测试帧摘要不变：确认/否认/管理消息/TEI 列表/应用层数据帧既有断言全过；**非测试上行业务帧（sid 0x01/0x03/0x04/0x06）摘要不含「测试帧/测试ID」**。
6. `test/test_csg_summary.py` 与 `test/test_gw_monitor_summary.py` 全过；`python release_check.py` 无 FAIL。
7. `test/test_csg_summary.py` 不再包含摘要逻辑的第二份复刻（单一实现原则），改由 `main_gui` 提供。
8. 新增用例走**整帧 → 解析 → 摘要**链路（不直调 helper），确保 gate 与分支接线被覆盖。

## Out of Scope

- Reflex Web 版摘要（后续同步）。
- 新增测试模式名称映射（沿用解析器既有 `_LEGACY_TEST_MODE_MAP`/`_EXT_TEST_MODES`）。
- 摘要列宽/截断策略调整、详情面板与单帧解析表格的字段展示（本次只改摘要文本）。
- 协议11（HDC 1.0）自有摘要改造——它复用协议10 摘要函数，自动获得本功能。

## Risks / Deferred

- 协议9 存在**没有** `测试模式/配置操作` 字段的测试帧（测试ID 0/1/2 类，数据区是频段/空），本次按 R2 回退到 `测试ID`/`扩展ID`/`通信频段` 表达；若你希望这类帧显示别的口径（例如把 `测试ID` 直接称为「测试模式」），改一行映射即可。
- 摘要是单行文本，测试帧信息变长后可能在窄列被截断（表格列 `摘要` 为 Stretch，全文可用 tooltip 查看）；如需压缩可后续加简写。
