# 协议9 链路层组帧（FC / PBH / MAC 头五层折叠）

## Goal

为协议9（新一代载波 / 通感一体化）补齐**链路层组帧**能力：当前组帧只到应用层（测试帧 BDU → 业务报文 → 应用层帧 → ED..EE 封装），**FC 帧控制、物理块头(PBH)、MAC 帧头三层的组帧完全没有实现**，因此无法构造可在信道收发的完整 MPDU。

要在「协议组帧」页把三层补上，并把页面重构为**五层折叠表单**（FC / PBH / MAC 头 / MSDU / ED），让用户逐层展开填写几十个字段后生成整帧；生成结果由协议9 解析器回读逐字段对拍。

用户原话：*"协议9，组帧功能，FC和MAC头的组帧这些没有设计啊，可以设计不同的表单输入后生成报文，由于字段非常的多，因此你需要在UI设计上考虑好，比如采用折叠窗口来触发对应的参数值填写，比如FC + PBH +MAC头+MSDU这样一个个折叠窗口进行填写"*。

## 背景（实测现状）

| 层 | 组帧 | 解析 | 出处 |
| --- | --- | --- | --- |
| FC 帧控制（16B，含 FCCS） | ❌ | ✅ 11 个变体 | `csg_new_gen_parser._parse_mpdu_*` |
| PBH 物理块头(4B) + PBCS | ❌ | ✅ | `_parse_pb_block` |
| MAC 帧头（32B/12B/4B） | ❌ | ✅ | `_parse_mac_frame` / `_parse_single_hop_mac` |
| MSDU / 应用层 | ✅ | ✅ | `csg_new_gen_frame_gen`（24 个测试模式） |
| ED..EE 封装 | ✅ | ✅ | `build_ed_frame`（plc2 / gx） |

- 现有组帧器 `csg_new_gen_frame_gen.py` 最外层即 `build_ed_frame`，**没有 FC/MAC/PBH**。
- 现有页面 `csg_test_frame_gen_widget.py`（465 行）为「模式选择 + 模式参数 + 应用层头 + ED 封装」四块平铺，无折叠。
- 解析侧位布局**已验证**（60 帧真实夹具 + 各层专项测试），是本次实现唯一的字段依据来源（详见 `research/03-parser-cross-check.md`）。

## 已确认的决策（用户选定）

1. **进入 Trellis 规划阶段**，先出 `prd.md` + `design.md` + `implement.md` 再实现。
2. **扩展现有「协议组帧」页**，做成 `FC → PBH → MAC → MSDU → ED` 五层折叠；**保留「输出层次」下拉**，仍可只输出应用层 / ED 等单层（兼容既有用法与既有测试）。
3. **MSDU 来源两者都要**：测试模式下拉 + 手工 HEX 覆盖（手工优先）。
4. **第一期范围**：SOF（BPLC + ISAC-PLC 数据帧）+ 信标帧 + SACK + 标准 MAC 长/短头 + PBH。
   **二期**：OFDMA/eFC、HRF 无线各布局、网间协调帧、单跳头、Bitloading 扩展帧、级联头、信标载荷表结构。

## Requirements

### R1. 组帧器：新增 FC 组帧（纯逻辑，`csg_new_gen_frame_gen.py` 或新增模块）

- 支持第一期 4 个变体：**SOF-BPLC**（表20）、**SOF-ISAC 数据帧**（表23）、**信标帧**（表18）、**SACK**（表30）
- FC 固定部分（表14）：定界符类型(3b) / 接入指示(1b) / SNID低位(4b) / 标准版本号(4b，字节12 高4位) / FCCS
- **FCCS 自动计算** = CRC-24(FC 字节 0-12)，小端 3 字节；不得让用户手填
- **接入指示默认为 1**（表16：MPDU 在宽带载波通信接入网络中传输）——否则解析器 auto 不走 MPDU 路径
- 各变体的字节 12 低 4 位正确落位（SOF-BPLC=扩展载波映射表索引 / SOF-ISAC 与 NET=SNID高位 / SACK=扩展帧类型 / 信标=符号数bit8+SNID高位+相线）
- 跨字节位域按「规范表字节号+比特位」打包，**不得按「首字节=高位」组装**（AGENTS 陷阱 54 的精神；本协议 FC 的 12bit TEI 就是跨字节）

### R2. 组帧器：新增 PBH + PBCS 组帧

- 物理块头 4 字节（表47）：序列号(16b,小端) + 聚合标志(1b) + 保留(15b)
- **PBCS 自动计算** = CRC-24(PBH + 块体 + 保留1字节)，小端 3 字节（表49 说明）
- 支持 PB 个数 1~4（第一期不做聚合帧级联头，聚合标志可置 0；若置 1 需在 UI 明示「级联头二期支持」）
- **块体长度 = PB总大小 − 8**；块体不足自动零填充（与解析侧补零行为一致）
- PB 总大小 ∈ {520, 264, 136, 72, 16}（BPLC 实际为 136/520）

### R3. 组帧器：新增 MAC 帧头组帧

- 标准长头 32B（表7）与短头 12B（表11）**共用字节 0-11 布局**，长头多出目的MAC(6B) + 保留(4B) + 保留(10B)
- 单跳头 4B（表12）**第一期不做**
- **MSDU 长度自动填**（= 实际 MSDU 字节数），不允许与内容不符
- **MAC 完整性校验(CRC-32) 自动计算** = CRC-32(**MSDU 载荷**，不含 MAC 头)，小端 4 字节
- TEI 位序遵循「低字节在前，低位在前」（表8 实例：目的TEI=0x123、源TEI=0x456 → `23 61 45`），须有测试钉住
- 各字段取值集合（广播方向/发送类型/版本/帧头类型）从**解析器既有常量**派生，不新建第二份清单

### R4. MSDU 层组帧

- MSDU 头按 MAC 帧头类型联动：帧头类型=0 → **18B 长头**（原始目的MAC 6 + 原始源MAC 6 + VLAN 4,LE + MSDU类型 2,LE）；=1 → **2B 短头**（VLAN 1 + MSDU类型 1）
- VLAN / MSDU类型 下拉取值限定在解析器认可的集合内（长头 `0~3 + {0x01,0x02,0x80}` 或 `0x8100+0x88E1`；短头 `0~3 + {0x01,0x02,0x80}` 或 `0x81+0x00`），非标准值给出可读告警
- 载荷来源**二选一**：① 测试模式（复用现有 24 模式）② 手工 HEX 覆盖（手工优先）
- 应用层帧复用 `build_app_frame`（端口号 1B + 报文标识符 2B,LE + 保留 1B + 业务报文）

### R5. UI：五层折叠表单（`csg_test_frame_gen_widget.py` 重构）

- 层次顺序固定：**① FC 帧控制 → ② 物理块 PBH → ③ MAC 帧头 → ④ MSDU → ⑤ ED..EE 封装**
- 每个折叠区标题栏显示：层名 + **当前层字节数** + 层 HEX 缩略（便于逐层核对）
- FC 区内部再按「通道/标准版本/定界符类型」**二次联动**：只显示当前变体的字段（第一期 4 个变体）
- 层可见性联动：**信标帧隐藏 ②③**（信标无 PBH/MAC）；**SACK 隐藏 ②③④**；**仅 ED/仅应用层输出层次**下只显示相关区
- 折叠状态与上次选择**持久化**（`config.json`，参照项目既有约定）
- 保留「输出层次」下拉，仍可只输出 应用层帧 / 业务报文 / 测试帧 BDU / ED 封装 / **整帧 MPDU**（新增）
- 右侧预览改为两段：**分层概览（各层字节数+HEX）** + **整帧逐字段回读**（由协议9 解析器 `parse_level="auto"` 产出）
- 所有新增按钮宽度走 `gui_utils.fit_btn_width`（AGENTS 陷阱 63：写死宽度必裁字）

### R6. 校验自动计算必须与解析侧同源可证

- FCCS / PBCS / MAC CRC-32 三处校验由组帧器自动计算，**用解析结果反证**：回读时对应行的说明须为「校验通过」
- CRC 实现**不得在组帧侧另写一份**：复用解析器既有 `_crc24` / `_crc32_ieee`（若需解耦则提取为模块级函数并让两侧共用，不改解析行为）

### R7. 测试（项目既有约定）

- 新增 `test/test_csg_link_frame_gen.py`（纯逻辑）：逐层 + 整帧回读、TEI 位序 oracle（`23 61 45`）、三处校验「校验通过」、越界与非法值报错、PB 大小与 cmt_index 自洽
- 新增/扩展 GUI offscreen 测试：五层折叠可见性联动、切变体后字段重建、输出层次各档、按钮不裁字
- **变异反证**：至少对「接入指示默认 0」「FCCS 覆盖范围改成全 16 字节」「MAC CRC-32 改成含 MAC 头」三条各做一次，确认测试变红
- 登记进 `release_check.py` 的 `CORE_TESTS` / `GUI_TESTS`
- 既有 `test/test_csg_new_gen_frame_gen.py`（144 项）与 `test/test_csg_frame_gen_gui.py`（117 项）**必须全绿**（这是「保留旧输出」决策的验收）

## Acceptance Criteria

- [ ] 能生成并通过解析器 `auto` 回读的**完整 MPDU**：SOF-BPLC、SOF-ISAC 数据帧、信标帧、SACK 各至少 1 例
- [ ] FC 全部字段「回读解析值 == 表单输入值」（含跨字节位域）；FCCS 行显示「校验通过」
- [ ] PBH 序列号/聚合标志回读正确；PBCS 行显示「校验通过」
- [ ] MAC 长头与短头各 1 例回读正确；「完整性校验(CRC-32)」显示「校验通过」；MSDU 长度与实际一致
- [ ] TEI 位序断言：目的TEI=0x123、源TEI=0x456 → 帧内字节 `23 61 45`（文档表8 自带 oracle）
- [ ] MSDU 头长度随帧头类型联动（0→18B / 1→2B），回读出现「MSDU头-原始目的地址」或「VLAN标签」对应行
- [ ] MSDU 载荷两种来源均可用，手工 HEX 覆盖优先级更高
- [ ] 五层折叠 UI：可折叠展开、切变体字段重建、信标/SACK 的层可见性正确、折叠状态持久化
- [ ] 「输出层次」各档可用（含新增整帧 MPDU）；既有 144 + 117 项测试全绿
- [ ] 新增测试通过且变异反证三条实测变红
- [ ] `python release_check.py` 无 FAIL（含 `--sync-iss`）

## Risks

| 风险 | 应对 |
| --- | --- |
| FC 字节0 漏置「接入指示=1」，帧能生成但解析器不进 MPDU 路径 | 默认值设为 1 + e2e 测试断言「定界符类型」行存在（抓此错） |
| 跨字节位域按「首字节=高位」组装 → 源/目的TEI 错位（协议11 曾整批踩过，AGENTS 陷阱 54） | 位打包统一走 `pack_bits`；用文档自带的 `23 61 45` oracle 断言 |
| MSDU 头长度与 MAC 帧头类型不一致 → MSDU 被当业务数据、树全错 | 长度由帧头类型自动决定，不给用户单独设；回读断言 MSDU 头字段行 |
| 三大校验覆盖范围写错（FCCS 应只覆盖前 13 字节；MAC CRC 不含 MAC 头） | 复用解析器 CRC 实现 + 回读断言「校验通过」+ 变异反证 |
| 重构 `csg_test_frame_gen_widget.py` 打破既有 117 项 GUI 测试 | 保留「输出层次」下拉与既有控件对象名；先跑基线再改；旧测试全绿作为验收条件 |
| PB 大小与 cmt_index 不自洽 → 解析多打「PB大小推断」行，用户困惑 | 以 PB 大小为主动输入反推 cmt_index，冲突时显式告警 |
| 字段数多导致实现期漏字段 | 表单元数据（字段清单）由 research 三份文档逐表核对，测试逐字段断言 |
