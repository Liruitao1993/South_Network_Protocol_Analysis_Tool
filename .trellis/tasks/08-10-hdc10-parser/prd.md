# HDC 1.0 协议解析器

## Goal

为南网解析工具新增一个独立的 HDC 1.0（国网双模互联互通 / Q/GDW 12087.42-2020）协议解析器，作为第 11 个协议出现在 GUI 下拉框中，支持 FC / MAC / MSDU / 应用层全链路解析，与现有国网新一代（HDC 2.0）解析器并列、互不干扰。

## Background

- 现有国网新一代（索引 10）解析器内部支持 HDC 1.0/2.0 自动区分，但 HDC 1.0 路径很多字段标为"保留"，解析深度不足
- HDC 1.0 与 HDC 2.0 在 FC 结构、MAC 帧头字段、应用层报文格式上差异显著，独立实现更清晰
- HDC 1.0 协议文档位于 `国网新一代协议/HDC-国网双模协议/`，共 3 册（物理层/数据链路层/应用层）

## Requirements

### R1：独立解析器类

- 新建 `hdc10_parser.py`，主类 `HDC10Parser`
- 主入口 `parse_to_table(frame_bytes, parse_level="auto", **kwargs)`，返回标准 7 元组列表
- 支持解析级别：`auto` / `fc_pb` / `fc_only` / `mac_only` / `pb_only` / `fc_mac` / `app`
- 支持通道参数 `channel`：`"plc"`（载波，默认）/ `"hrf"`（微功率无线）

### R2：FC 帧控制解析（16 字节）

- 定界符类型（3bit）、网络类型（5bit）、网络标识 NID（24bit）
- 可变区域按 4 种定界符类型 + 2 种通道分别解析：
  - 载波信标帧：信标时间戳、源 TEI、分集拷贝模式、符号数、相线
  - 载波 SOF 帧：源 TEI、目的 TEI、LID、帧长、物理块个数、符号数、广播/重传/加密标志、分集拷贝模式、扩展模式
  - 载波 SACK 帧：接收结果、接收状态、源 TEI、目的 TEI、物理块个数、信道质量、站点负载、扩展帧类型
  - 载波网间协调帧
  - 无线 SOF / SACK / 信标帧（各自不同字段布局）
- 标准版本号（4bit，应恒为 0）
- FCCS 校验（CRC-24）显示与验证

### R3：物理块 PB 解析

- PB 头（1 字节）：序列号（6bit）、帧起始标志、帧结束标志
- PB 体 + PBCS（3 字节，CRC-24）
- 支持多 PB 聚合（1~4 个）
- 信标帧 PB 结构不同（信标载荷 + BPCS + PBCS）
- pb_only 模式，需配合 `frame_type` 参数

### R4：MAC 帧头解析

- **标准帧（长帧头，版本=0）**，16 字节固定域：
  - 版本、原始源 TEI、原始目的 TEI、发送类型、发送次数限值
  - MSDU 序列号、MSDU 类型、MSDU 长度
  - 重启次数、代理主路径标识、路由总跳数、路由剩余跳数
  - 广播方向、路径修复标志、MAC 地址标志
  - 组网序列号
  - MAC 地址标志=1 时追加源/目的 MAC 地址（各 6 字节）
- **单跳帧（短帧头，版本=1）**，4 字节：
  - 版本、消息类型、MSDU 长度
- ICV（CRC-32）完整性校验值显示与验证

### R5：MSDU 与应用层解析

- MSDU 类型分发：0=网络管理消息，48=应用层报文，49=IP 报文
- 应用层通用头：报文端口号（1B）+ 报文 ID（2B 小端，高 4 位安全模式 + 低 12 位业务 ID）+ 报文控制字（1B）
- 业务报文深度解析（按报文 ID 分派）：
  - 抄表类（0x001/0x002/0x003）：上下行格式、协议版本、报文头长度、配置字、规约类型、转发数据长度、报文序号、选项字
  - 校时（0x004）
  - 事件上报（0x008）：方向位、启动位、功能码、电能表地址
  - 通信测试（0x006）
  - 从节点注册（0x011/0x012/0x013）
  - 确认/否认（0x020）
  - 升级类（0x030~0x036）：开始/停止/传输/查询状态/执行/查询信息
  - 台区户变关系识别（0x0A1）
  - 查询 ID 信息（0x0A2）
  - 精准校时（0x0A3）
  - 抄控器相关（0x040/0x041）
  - 配电信息上报（0x0A4）
  - 鉴权安全（0x0A0）

### R6：网络管理消息（MME）解析

- 管理消息头：MMTYPE（2B 小端）+ 保留（1B）+ 报文内容
- 实现常见 MME 类型：关联请求/确认、心跳检测、发现列表、离线指示等
- 可参考 `gw_new_gen_mme_parser.py` 框架，按 HDC 1.0 文档适配字段

### R7：GUI 集成

- 协议下拉框新增第 11 项："HDC 1.0 双模互联互通"
- 协议索引 11，所有协议切换逻辑同步修改
- 解析级别下拉框（同国网新一代风格）
- 通道选择（PLC / HRF）
- PB 帧类型选择（pb_only 模式）
- 批量解析分派
- 查询页：报文 ID 查询
- 校验器：新增 `HDC10Validator`
- 组帧 / 预设命令页：不显示（R8 范围外）
- 实时监控器：支持 96..16 HPLC 包装格式（R8 范围外）

### R8：校验器

- 新增 `validator/hdc10_validator.py`，继承 `BaseValidator`
- FC FCCS 校验（CRC-24）
- PBCS 校验（CRC-24）
- ICV 校验（CRC-32）
- 长度校验、字段合法性检查

## Out of Scope

- 实时监控器集成（监控 widget + TCP 监控）：后续迭代再加
- 组帧功能：HDC 1.0 不显示组帧/预设命令页
- NiceGUI / Textual / Reflex Web 版本适配
- 系统集成中的协议关联（Notepad++ 右键等）可选扩展
- 物理层前导码 / 同步序列解析（软件解析器不涉及）
- OTA 升级数据的深度校验（仅做头部解析）

## Acceptance Criteria

- [ ] `HDC10Parser` 类可被导入，`parse_to_table` 可调用
- [ ] FC 4 种定界符类型（信标/SOF/SACK/网间协调）+ 2 通道共 7 种可变区域格式全部解析
- [ ] 标准 MAC 帧头 16 字节字段 + 可选 MAC 地址扩展全部解析正确
- [ ] 单跳 MAC 帧头 4 字节解析正确
- [ ] 应用层至少 15 种报文 ID 可解析出头部字段
- [ ] GUI 下拉框第 11 项可选，切换后解析结果正确
- [ ] 批量解析可正常工作
- [ ] 查询页有 HDC 1.0 报文 ID 数据
- [ ] FCCS / PBCS / ICV 三种 CRC 校验显示正确
- [ ] pyinstaller 打包成功，exe 可运行
- [ ] 不破坏现有 11 个协议的解析功能

## Open Questions

无阻塞性问题。以下为默认假设，用户可调整：

1. 监控器 / TCP 监控暂不集成（Out of Scope）
2. 组帧功能不做（Out of Scope）
3. 管理消息（MME）只实现常见类型，不追求全覆盖
4. 应用层业务数据 DATA 域（如 645 报文内容）不解码，仅显示原始 hex（透明展示）
