# 协议8 698.45 文件传输升级（分布式产品升级）

## Goal

在桌面版新增「升级」标签页（**仅协议8 DL/T 698.45 可见**）：拖入二进制升级文件包 → 按可设置的每包字节数分包 → 通过串口按 698.45 文件分块传输（OI `0xF001`）逐包下发，每包等待设备确认帧 → 全部传完后发送「执行升级」命令，由设备自行完成升级。全程有进度显示，SA 地址可设置（默认通配地址）。

## 背景与依据

- 参考流程与逐字节示例：`协议文档/8.698.45协议/代理升级流程.docx`（含 2 张帧结构表 + 实帧 hex）。
- 对象定义：`协议文档/8.698.45协议/面向对象的用电信息数据交换协议(20210910).md` 附录 A.1（`F001 | 18 | 文件分块传输管理`）与表 188（文件传输类属性）/表 189（方法）。
- 既有实现：`DLT69845FrameGenerator.generate_action_request_normal()`（ACTION-Request Normal 组帧）、`DLT69845Parser`（链路层解析）、`AXDRCoder`（A-XDR）。
- 仓库内**当前没有任何文件传输/升级相关代码**（已全仓检索确认）。

### 三步命令（协议事实）

| 步骤 | APDU | OMD | 参数（A-XDR） |
|---|---|---|---|
| ① 启动传输（让设备进入接收升级包状态） | `ACTION-Request Normal` (07 01) | `F0 01 07 00`（OI `0xF001` 大端 + 方法7 + 模式0） | `structure{文件信息 structure, 传输块大小 CHOICE{[18] u16 短帧 / [6] u32 长帧}, 校验 structure{类型 enum(0=CRC,1=md5,2=SHA1), 值 octet-string}}` |
| ② 写文件（每包一帧，逐包确认） | 同上 | `F0 01 08 00`（方法8 写文件） | `structure{块序号 long-unsigned, 块数据 octet-string}` |
| ③ 执行升级 | 同上 | `F0 01 0D 00`（方法13 执行升级） | `structure{执行升级时间 date_time_s（全 FF = 立即执行）, 软件许可 CHOICE{NULL[00], License[09] octet-string}}` |

`文件信息 ::= structure{源文件 visible-string, 目标文件 visible-string, 文件大小 double-long-unsigned, 文件属性 bit-string(SIZE(3))（bit0读/bit1写/bit2执行）, 文件版本 visible-string, 文件类别 enum{当前设备文件(0), 其他设备文件(1)}}`（表188 属性2）。

设备对每帧的应答为 `ACTION-Response Normal`（`87 01`），`DAR=0` 表示成功（doc 实帧：`87 01 00 F0 01 07 00 00 00 00 00`）。

## 范围

**做**：桌面 PySide6 新增「升级」标签页（协议8 可见）；升级文件拖入/选择；分包；三步命令组帧；串口逐包发送 + 逐包确认 + 超时 + 逐包重试；进度条与日志；每包字节数可设；SA 地址可设（默认通配）；文件信息字段可编辑；校验类型/值可设或按算法自动计算。

**不做**（已与用户确认）：Web 版；doc 中的厂商私有「查询分布式版本」（OI `0xFFFE`，非标准）与「5 轮整包重发」外层循环；暂停/恢复/终止传输（方法9~14 中除 7/8/13 外的其它方法）；安全/密文模式（`SECURITY-Request`）。

## 功能需求

- **FR1 入口**：新增「升级」标签页，仅在协议下拉选「698.45 协议」时可见；其它协议下隐藏（沿用现有 Tab 显隐机制）。
- **FR2 升级文件**：支持拖放二进制文件到页面（并保留「浏览…」按钮作为等价入口）；显示文件名与文件大小；文件为空/不可读时给出可读错误且不进入后续状态。
- **FR3 分包**：按「每包字节数」把文件切成 N 包，最后一包为余数；每包字节数可设置（默认 **600**），设置值须校验（正整数、上限合理）。
- **FR4 启动传输**：发送前可编辑文件信息（源文件/目标文件/文件版本/文件大小自动取实际大小/文件属性/文件类别）与传输块大小、校验类型与校验值（校验值支持自动计算与手工填写）。
- **FR5 逐包传输**：按包序号顺序发送；每发一包等待设备确认帧（`ACTION-Response Normal` 且 `DAR=0`）；确认后才发下一包；确认帧 DAR≠0 或超时按「逐包重试」处理（重试次数可设，用尽则整轮失败并停止）。
- **FR6 进度与统计**：进度条显示已传字节/总字节（及包序号 x/N）；日志区显示每帧 TX/RX 的 hex 与解析摘要、失败原因；支持中止。
- **FR7 执行升级**：全部包确认成功后，按提示发送执行升级命令（执行升级时间默认「全 FF = 立即执行」可改为指定时间；软件许可默认 NULL）；发送后给出结果提示。
- **FR8 SA 地址**：SA 可设置：地址类型（单地址/通配/组/广播）、地址长度、地址字节；**默认通配地址**（类型=通配、长度 6、地址字节 `AA AA AA AA AA AA`）；CA 可设置（默认 0）。
- **FR9 串口**：复用主窗口共享串口通道（不新增端口/波特率控件，跟随顶部「串口配置」）；未连接时禁止开始并给出提示。
- **FR10 纯逻辑分层**：组帧/分包/确认判定/校验计算放在无 Qt 依赖的纯逻辑模块，可脱 GUI 单测。

## 非功能需求 / 约束

- 遵循 `AGENTS.md` 各条：新 UI 组件独立文件、能力注入（widget 不 import `main_gui`）、新增 QThread 必须 `thread_registry.track`、协议能力经 `protocol_registry.ProtocolSpec` 声明而非硬编码。
- 多字节字段两层字节序不可混用：链路层（L/HCS/FCS）小端，APDU 内 A-XDR 大端。
- 按钮宽度不得写死（`gui_utils.fit_btn_width`）；不新增 pip 依赖。
- 完成功能后同步 `main_gui.py:CHANGELOG` 与 `APP_VERSION`、README、AGENTS.md 相关章节（§3/§5.6/§8 新增陷阱）。

## 开放问题（实施前必须定论，写入 design.md）

1. **校验算法口径**：`校验类型=CRC(0)` 时 `校验值` 的算法/字节序/覆盖范围（doc 仅给 4 字节 `7F 7E D9 D2`，无对应文件可复算）。默认取 CRC32，但必须给出「可手工覆盖」的通道，避免自证错误。
2. **文件属性 bit-string 位序**：`SIZE(3)` 的 3 个 bit 在字节中的摆放（doc 实值 `E0` 推断为 3 bit 全 1 = 可读/可写/可执行），需与 `AXDRCoder` 的 bit-string 实现口径统一。
3. **块序号起点**：doc 实帧首块为 `0`（0 基）。是否需允许 1 基以兼容个别厂商。
4. **`date_time_s` 编码长度与全 FF 写法**：需按本仓库 `AXDRCoder` 实现确认（LINK 预连接里用的 10 字节 date_time）。
5. **传输块大小上界**：串口单帧长度上限（与 `serial_worker` 的缓冲区/超时配合）。
