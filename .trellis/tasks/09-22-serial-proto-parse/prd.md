# 串口工具：命令带协议字段 + 按协议断帧与解析输出

## Goal

让「串口工具」从「哑终端」变成**协议感知的联调工具**：

1. **命令表新增「协议」字段** —— 新增/编辑命令时提前告知该命令属于哪个协议（12 选 1，或「不解析」）。
2. **接收按该协议断帧** —— 不再靠时间窗口猜帧边界，而是用协议自身的长度域/定界符把 RX 字节流切成完整帧。
3. **按该协议解析并直接输出文字** —— 每个完整 RX 帧在日志里紧跟解析结果（摘要 + 字段明细），不必再复制到「单帧解析」页。

现场价值：现场联调时发一条国网/南网命令，RX 的 208 字节响应**直接显示成一行完整帧 + 中文解析**，一眼看出控制域、地址域、AFN、数据单元是什么。

## Background（已确认事实）

### 现状（`E:\python\南网解析工具\`，1.23.46 未提交）

- 「串口工具」标签页已集成（任务 `09-22-serial-tool-integration`），命令表 4 列：名称 / 发送数据 HEX / 匹配方式 / 预期响应；复用主窗口共享 `serial_worker`。
- 接收两模式：**原始数据**（帧结构优先 + 时间聚合兜底）与**按帧尾分割**。原始模式已能按长度域切分 68 家族帧（`serial_tool_widget._declared_frame_len`：南网/国网 `68+L(2B 小端)`、698.45 `68 L L 68` 即 `L+3`、645 `68 A6 68` 即 `L(1B@9)+12`），末字节必须为 `16H` 才算自证。
- **但帧边界仍靠猜**：三种 68 结构靠「第 4 / 第 8 字节是不是 68H」互斥判别，属于启发式；非 68 家族（HDLC / DLMS Wrapper / PLC RF / 新一代 / HDC 1.0）完全没有分帧能力，只能靠帧尾或时间聚合。
- **接收侧没有任何解析能力**：日志只有 `[RX] 68 D0 00 …` 原始 hex。

### 可复用的既有能力（不重造）

- `protocol_registry.py`：`all_protocols()` / `get_protocol(index)` / `combo_labels()` 提供 12 协议元数据（`index` / `name` / `short_name` / `extract_strategy` / `parser_wrapper` / `parser_key`），新增协议只改这里。
- `main_gui.MainWindow._get_current_parser(protocol_index)` → `protocol_registry.build_gui_parser(...)`，返回的对象统一提供 `parse_to_table(frame_bytes) -> list[(字段名, 原始值, 解析值, 说明, byte_start, byte_end)]`。
- `main_gui.MainWindow._get_summary_from_table_data(table_data, protocol_index) -> str`：从解析表提取一行摘要。
- `hdlc_parser.HDLCParser`：`parse_to_table` / `parse_wrapper_to_table` / `parse_apdu_to_table` / `_hdlc_verify`（FCS 校验）。
- 主窗口已用同一约定向懒加载标签页注入依赖（`tab.set_serial_worker(self.serial_worker)`），本任务沿用该约定注入**解析回调**。

## Key Decisions（已与用户确认）

1. **协议字段的载体**：命令表新增第 5 列「协议」，值 = 协议索引（int）或 `None`（不解析）；在 `SerialCommandDialog` 用下拉选择。落盘键 `protocol`；导出裸列表时**保留**该键（源工具忽略未知键，双向兼容不破）。
2. **接收用哪个协议**（用户选定 `follow_tx`）：用**最近一次发送命令的协议**（串口是问答式，RX 是 TX 的响应）。发送时锁存 `_last_tx_protocol`；接收分帧与解析都用它。若为 `None` → 完全回落现有 raw/frame 两模式（行为不变）。**不**做页面级独立「接收协议」下拉。
3. **解析在日志内联输出**（不是弹窗）：每个完整帧先出 `[RX] <hex>` 原始行，紧跟 `[解析·<协议短名>] <摘要>` 与缩进字段行。
4. **失败不伪造**：解析抛异常或返回退化结果（空表）时输出 `[解析] 失败：<原因>`，不拿退化结果冒充成功（与 TCP 监控同一原则）。
5. **分帧失败回落**：分帧依据不可信（长度越界 / 定界符缺失 / 末字节自证失败）时，该帧交回现有「帧结构优先 + 时间聚合」路径，**错切帧比不切更糟**。
6. **分帧覆盖范围**（用户选定 `seven`）：精确流式分帧实现 7 个协议 —— 0/7（`ft12_68`）、6（`dlt645`）、8（`dlt698_45`）、2/3（`hdlc_7e`）、4（`dlms_wrapper`）；1/5/9/10/11 无自证依据，回落既有路径。
7. **流程**：走 Trellis（本任务 `09-22-serial-proto-parse`）。

### R2 按协议流式分帧

- AC2.1 发送命令时锁存该命令的协议索引；RX 分帧与解析使用锁存值。
- AC2.2 索引 0 / 7：`need = buf[1] | buf[2] << 8`，收满 `need` 字节且末字节为 `16H` 时产出整帧（一行一帧）。
- AC2.3 索引 6：`need = buf[9] + 12`，需 `buf[7] == 0x68` 且末字节 `16H`。
- AC2.4 索引 8：`need = ((buf[1] | buf[2] << 8) & 0x3FFF) + 3`，需 `buf[3] == 0x68` 且末字节 `16H`。
- AC2.5 索引 2 / 3：按 `7EH` 定界切帧，帧内 `7DH 5EH` 还原为 `7EH`、`7DH 5DH` 还原为 `7DH`；连续 `7EH` 视为共享标志位（不产生空帧）；首尾标志位齐全才算完整帧。
- AC2.6 索引 4：`need = 8 + int.from_bytes(buf[6:8], "big")`，需 `buf[0:2] == 00 01` 且长度在合理区间。
- AC2.7 分帧依据不可信（长度越界 / 自证失败 / 该协议无依据）时**不得**产出帧，交回现有「帧结构优先 + 时间聚合」路径；无自证依据的协议（1/5/9/10/11）行为与改动前完全一致。
- AC2.8 未收全的帧必须留在缓冲等待（受既有 `FRAME_IDLE_MS` / `FRAME_HOLD_MAX_MS` 上限约束），不得因等待而丢字节。
- AC2.9 一次交付里含多帧时逐帧产出（N 帧 → N 行），RX 帧数按帧计。

### R3 按协议解析并输出文字

- AC3.1 每个产出的完整 RX 帧，若其协议非 `不解析`，按该协议解析并在日志输出：`[解析·<协议短名>] <摘要>` + 缩进字段行。
- AC3.1b **发送（TX）同样按该条命令自己的协议解析**，与接收对称（1.23.48 补，实测反馈「发送为何没有解析」）：TX 解析行入 TX 队列，与 `[TX]` 原始行同批刷出。
- AC3.2 字段行格式：`字段名 = 解析值`（解析值为空时用原始值），有说明时追加 `  <说明>`；字段名与值不得为空串导致出现 ` = `。
- AC3.3 字段行数上限 `parse_max_lines`：**默认 `0` = 不限制**（可选 0~2000，0 显示为「不限制」）；非 0 时超限截断并输出 `…（共 N 行，已省略 M 行）`。**依据**：现场实测国网「查询从节点ID信息」一条应答帧就有 113 行解析（22 行帧级字段 + 1 行从节点总数量 + 15 个节点 × 6 行），默认截断会让现场看不到完整结果。
- AC3.4 解析异常、或返回空表 / 退化结果时，输出 `[解析] 失败：<原因>`（fail 配色），**不得**输出半成品字段。
- AC3.5 页面新增「显示解析」开关（默认开），同时管辖 TX 与 RX；关闭时只输出原始行，不解析、不耗时（provider 零调用）。
- AC3.6 高速接收/发送时沿用既有 burst 策略：各自队列的 `raw` 条数超 `LOG_FLUSH_BURST` 时只输出「摘要 + 首末帧」，同批解析明细整批丢弃（防日志刷屏拖慢界面）。
- AC3.7 解析在 GUI 线程执行（与既有响应匹配同口径），单帧解析耗时不得阻塞到影响发送定时（若实测有影响，按既有取舍记录并另开任务下沉到 worker 线程）。
- AC3.8 解析器实例通过注入的**解析回调**获取（由 `main_gui` 提供），`serial_tool_widget` **不 import `main_gui`**、不直接持有 `MainWindow`。

### R6 匹配判决可诊断（1.23.50 补，实测报障/诉求）

- AC6.1 **匹配必须按累积接收缓冲比对**，不能按串口单次交付的块：驱动会把一帧拆成多次交付（实测 208 字节国网帧 = 77+92+36+3），按单次交付比对时「预期 = 整帧」永远匹配不上（与接收模式无关 —— 匹配吃原始交付块，不是切好的帧）。
- AC6.2 累积缓冲有上限（`MATCH_BUFFER_MAX = 8192`），**每次发送时清空**（一问一答窗口重新开始）、待匹配队列清空时清空，避免用上一次响应的字节误判本次。
- AC6.3 **「队首连续匹配」语义不得改变**（同一批数据仍可连续命中多项）。
- AC6.4 发送时输出匹配规则：`[匹配] #n 等待响应：<方式>(<key>)，预期 = <HEX 预览>`。
- AC6.5 命中时输出方式与预期；超时输出 **5 行**诊断：标题 + `匹配方式` + `预期响应` + `期间收到（共 N 字节）` + `诊断 = <为什么没匹配上>`。
- AC6.6 `match_failure_reason()` 按 6 种匹配方式分别说明差在哪（预期串未出现 / 长度不一致 / 首个不同字节偏移 / 结尾不符 / 正则未匹配 / 期间未收到任何数据），并能识别最常见误填「**预期响应与发送数据完全相同**」。
- AC6.7 匹配日志走 RX/TX 队列，享受 burst 保护（高速时不刷屏）。

### R7 勾选发送 + HEX 容错 + 正则匹配（1.23.52 补，实测诉求/报障）

- AC7.1 命令表新增第 0 列「选择」勾选框；提供 **全选 / 全不选 / 反选** 与「已选 N / M 条」计数。
- AC7.2 **发送只发勾选的命令**（按表内顺序）；勾选状态存命令 `enabled`，随配置落盘读回；**旧配置无该键 → 全选**（与旧版本「只能全部发送」等价）。
- AC7.3 筛选发送必须把「筛选后下标」映射回 `commands` **原下标**（`SerialSendWorker.index_map`），否则名称 / 协议 / 匹配规则张冠李戴。
- AC7.4 一条都没勾 → 明确提示且**不启动**发送；发送日志标明「N/M 条命令（已勾选）」。
- AC7.5 勾选框必须能被**鼠标点击**切换（`NoEditTriggers` 不得阻碍），并回写 `enabled`；重建表格期间不得因 `itemChanged` 反复落盘。
- AC7.6 **`hex_str_to_bytes` 必须容忍连续无分隔的 hex**（`6812004116`）：按字节切；半角/全角逗号、顿号、半角/全角分号、斜杠、竖线、连字符、全角空格都作分隔符；容忍 `0x` 前缀；仍拒绝「连续串奇数位」与「含非 hex 字符」。**依据**：实测报障「明明是对的却提示不是有效的 HEX」。
- AC7.7 「不是有效 HEX」的提示必须给**可读原因**（`hex_input_error()`：含哪个字符、第几位；或片段字符数为奇数），不能只说「格式不对」。
- AC7.8 **「正则表达式」匹配方式下「预期响应」是正则文本、不是 HEX**：`normalize_command` 只校验正则语法（空正则也降级）；`_on_sent` 用 `encode('latin-1')`；日志按 `正则 <文本>` 展示（不用 repr）。**依据**：旧实现把正则按 HEX 校验 → 静默降级成「不匹配」、待匹配项不入队，匹配永远不发生。

### R8 HEX 通配匹配（1.23.53 补，实测诉求）

- AC8.1 新增匹配方式 **「HEX 通配（XX=任意字节）」**：预期响应直接写 HEX + `XX`（如 `68 D0 XX XX XX XX`），**沿用「测试方案」的既有约定**（`test_plan_widget._match_frame`：逐字符走、遇 `XX` 跳过一个字节）。
- AC8.2 `XX` 可内嵌连续串（`68D0XXXX16`）；`??` 是等价别名；分隔符复用 HEX 容错那一套（空格/半角全角逗号/顿号/分号/斜杠/竖线/连字符）；**单独的 `X` 不算通配**（必须 `XX`）。
- AC8.3 语义 = **包含式**（在累积接收数据里任意位置查找，跨交付块）；可选锚点：开头 `^`、结尾 `$`（`^68D0XX` / `XX16$` / `^…$` 全长）。
- AC8.4 命中日志给出**命中偏移**；`contains` 也报出位置（统一入口 `match_offset()`）。
- AC8.5 失败诊断区分「模式比收到的数据长」与「通配模式未在收到的数据中匹配到」；不参与「预期 = 发送值」误填提示。
- AC8.6 `normalize_command` 对 `hex_wildcard` 只校验通配模式合法性（非法才降级），**不得**像旧正则那样被静默降级。
- AC8.7 对话框按所选方式**动态切换占位符与说明**：HEX 通配给出 `XX`/`^`/`$` 写法；正则说明里点明「字节要写 `\xNN`」「忽略大小写会混淆 `\x68`/`0x48`」「`.` 不匹配 `0x0A`」三个坑并建议二进制帧改用 HEX 通配。

- AC9.2 图标取 lucide（`circle` / `loader` / `check-circle` / `x-circle` / `alert-triangle`）并**按状态上色**（绿/红/蓝/橙/灰）；名称文字同色系、tooltip 写明状态；表格下方有图例。
