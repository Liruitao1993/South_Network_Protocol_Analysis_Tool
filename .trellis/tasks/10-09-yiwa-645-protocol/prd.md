# 新增协议13：依瓦定制645（解析器+校验器+组帧+查询页+预设+Web）

## Goal

在桌面 GUI 与 Reflex Web 两端接入「依瓦定制 645 协议」（依瓦定制645协议 V1.0，2026-06-24 陈工），
使其成为**与现有 12 个协议并列的独立协议（下拉索引 13）**，具备完整的单帧解析、CS 校验、批量解析、
DI 查询、协议组帧与预设命令库能力。

该协议与标准 DL/T 645-2007 **结构不兼容**（地址域字节序相反、数据域长度被拆到 COMMAND 低 4 位、
数据项 ID 只有 2 字节、数据域带 +0x33 混淆），因此**不复用协议 6 的解析路径**，而是新增独立实现。

## 协议事实基线（实现必须与此一致）

### 帧结构

```
68H │ A0 A1 A2 A3 A4 A5 (6B) │ 68H │ COMMAND (1B) │ L (1B) │ DATA (变长) │ CS (1B) │ 16H
```

| 项 | 定义 |
| --- | --- |
| 地址域 | **高字节在前**：`123456789012` → `12 34 56 78 90 12`；广播 = `AA AA AA AA AA AA`；表号 >12 位取低 12 位，<12 位高位补 0 |
| COMMAND | Bit7~Bit4 = 模式；**Bit3~Bit0 = 数据域长度高 4 位** |
| 数据域长度 | `((COMMAND & 0x0F) << 8) | L`，12 bit 有效（0x000~0xFFF） |
| CS | 从第一个 `68H` 起、到 CS 之前所有字节逐字节模 256 求和（对**未减 0x33 的原始字节**计算） |
| DATA 长度 | = 数据域长度 = 所有 `ID(2B) + FL(1B) + 数据项(FL 字节)` 之和 |
| 数据域混淆 | 发送时数据域**逐字节 +0x33**，接收时**逐字节 −0x33**；地址/COMMAND/L/CS 不参与混淆 |
| DATA 结构 | 重复的 `ID(2B)` + `FL(1B)` + `数据项(FL 字节)`；**主站请求不带 FL（只有 ID）**，模块回复才带 `FL + 数据项` |

### 模式（COMMAND 高 4 位）

| 模式 | 命令码 | 说明 |
| --- | --- | --- |
| 读模式 1 | `0x10` | 读取单个数据项 |
| 读模式 2 | `0x20` | 批量读取（多个 ID 连续） |
| 透传模式 1 | `0x30` | 转发到底层 645 表 |
| 透传模式 2 | `0x40` | 转发到底层 645 表 |
| 写模式 | **文档未定义**（章节缺内容） | 见「已知文档缺陷」 |

### 附录 A 数据项定义（全表仅 2 条）

| ID | 名称 | 说明 |
| --- | --- | --- |
| `00 10` | 设备类型 | 长度 1 字节；`01` = 电表 |
| `00 20` | 设备号 | 长度可变（最大 12 字节） |

### 序言「接收字节定义，避免丢包」硬约束

1. 帧内字节间隔 < 40ms
2. 上位机发送/接收每个字节间隔 < 40ms
3. 9600 bps、8 位数据位、偶校验、半双工

### R2 帧解析（核心）

- R2.1 识别有效帧：长度 ≥ 12、`data[0]==0x68`、`data[7]==0x68`、`data[-1]==0x16`。
- R2.2 地址域按**高字节在前**解析为 12 位十进制表号（去前导 0），并识别广播地址（`AA×6`）。
- R2.3 长度域按 `((COMMAND & 0x0F) << 8) | L` 解析，长度行须同时展示低 8 位与高 4 位的来源。
- R2.4 模式识别：`0x10`/`0x20`/`0x30`/`0x40` 按文档命名；其余值给出「未知模式」并继续解析（不得空白返回）。
- R2.5 数据域按 **−0x33** 还原后切分为数据项序列，每项输出 `ID / FL / 数据项原始值 / 数据项说明`；
  附录 A 命中的 ID 展开为业务名称与枚举（如 `00 10` = 设备类型 → `01` = 电表）。
- R2.6 主站请求帧（无 FL）与模块回复帧（带 FL）须自动区分：按「数据域能否被 `ID+FL+数据项` 完整切分」判定，
  并在解析结果中标注判定结论；不确定时同时给出两种解释并插入 `⚠` 提示行。
- R2.7 CS 校验：计算值 vs 帧内值，不一致时**仍完整解析**（项目强制约定），并在表格插入 `⚠ 校验和错误` 行，
  行内给出帧内值、**正确值**与计算规则。
- R2.8 长度域声明值与实际数据域字节数不一致时，仍尽力解析，`valid=False` 并插入醒目 `⚠` 提示行。
- R2.9 解析结果返回嵌套 dict，键名遵循项目约定（`原始值`/`十进制`/`说明`/`偏移`/`长度` 等），
  每行带**字节偏移区间**以支持 GUI 字节高亮；偏移区间不得越界、不得重叠错乱。
- R2.10 提供 `parse` / `parse_to_table` / `get_summary` / `is_frame` / `calc_checksum` 五个方法（与既有解析器同形）。
- R2.11 批量解析提取策略 `yw645`：在混合日志中按「`68` + 6 字节地址 + `68` + COMMAND + L + … + CS + `16`」自证提取，
  且**与已有 68 家族（南网/国网/698.45/645）互斥**（靠末字节 `16H` 与 `data[7]==0x68` 联合自证）。

### 由示例推出的附加事实（实现必须遵守）

- **F1 地址域大端已被三条示例独立自证**：`12 34 56 78 90 12`→123456789012、`10 30 00 00 00 10`→103000000010、

  透传示例 X3/X5/X6/X7/X8/X9 给出的**是线上已 +0x33 的形态**——证据：X6 `36 13` −0x33 = `03 E0`（文档明写「减33后可看出E003」）、
  X5 `37 14 64 65 66 67 68 69 6A 6B 6C 6D 63 6E` −0x33 = `04 E1 31 32 33 34 35 36 37 38 39 3A 30 3B`（后 12 字节恰为 ASCII 数字串）。
  ⇒ 实现必须同时接受两种形态（R3.1 的自动判别），测试须**对同一帧的两种形态断言相同字段结果**。
- **F4 X7 的 DATA 不可作为结构 oracle**：文档 L236 自述「数据域减33后可看出，目前是虚拟，不一定正确」。
  X7 减 0x33 后为 `03 E0 10 90 00 00 00 00 62 C3 10 27 00 00 81 C1 23 55 05 01 10 10 05 80 C3 00 40 7D C3 5F 7E C3 01 7F C3 00`，
  按 `ID+FL+数据` 切分**无法自洽**。X7 只用于验证地址/长度/CS 三项规则，**不得**用于断言数据项切分结果。
- **F5 帧尾 `16H` 不可作为切帧依据**：数据域已 +0x33，0x16 完全可能出现在数据域内部；
  X7 的数据域末字节是 `33`、CS 是 `0x31`。⇒ 批量提取/串口分帧**必须按长度域定位帧尾**，不得搜索 0x16。
- **F6 附录 A 的 `00 10`/`00 20` 是线上字面字节**（X2 的线上数据为 `00 10 …` 且未被混淆，若按小端 u16 读则为 0x1000/0x2000）。
  ⇒ **主键按字面字节**；另提供字节交换备选查表（见 D2）。
