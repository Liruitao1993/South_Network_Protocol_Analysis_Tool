# Web 批量解析能力对齐（摘要 / 前缀剥离 / 行号 / 导出）

## Goal

让 Web 批量解析与桌面在**同一份现场日志**上得到相同的帧集合与逐字相同的摘要，并补齐 Web 缺失的定位/导出能力（父任务 `research/web-parse-audit.md` §1）。

依赖：`09-15-web-parse-p0-fixes`（失败判定/剔除/kwargs）→ `09-15-web-shared-parse-core`（共享核心）之后执行；本任务只做「共享核心之上」的能力补齐，不得再引入第三份实现。

## Confirmed Facts

- 摘要三份实现（B1~B4）：协议10 用协议9 摘要函数（`web_utils.py:620-621`）；协议11 用 Web 独有 `get_hdc10_summary`，其 `业务类型ID` 键（596）与 `hdc10_parser.py:2029-2032` 实际字段名不匹配 → 恒不命中；协议0/7/8 退化为关键词兜底；桌面 1.23.10 的测试模式摘要在 Web 完全不存在。
- 前缀剥离（B5~B7）：Web 缺 `fc_payload_data := '…'` 跨行引号状态机（桌面 `main_gui.py:4736-4840/4872-4930`）、缺 `mac_only` 直通（4942）、缺协议10/11 的 EDA5/TCP 包装剥离（4855-4861/4933-4937）、app 扫描阈值不同（`web_utils.py:122` `len-i>=8` vs 桌面 `while i+32<=len`）。
- 行号（B8/B9）：Web 提取返回纯字符串、无 ED 逐帧分支（桌面 `7479-7541` 三条分支 + `[ED:类型]` 摘要前缀 + `_src_line`）→ 无「定位原始日志行」与快照回看。
- 诊断（B12/B13）：Web 空输入只报一句「未找到有效帧数据」；异常状态字面量 `错误/解析错误` 与桌面 `异常` 不一致。
- 导出（B14/B15）：Web CSV 只有 6 列汇总（无字段详情）；摘要列与「协议/类型」列在 Web 是同一文本（`reflex_web.py:941-942` vs 桌面 `_get_frame_type_name`）。
- 显示上限：`batch_display_limit = 300`（`reflex_web.py:72`）——**保留**（前端渲染保护），但需给出「导出包含全部」的明确提示与分页/加载更多入口。

## Requirements

### R1 摘要与桌面同源同文

- Web 摘要全部改由共享核心提供（`summary_kind` 驱动），覆盖协议0/7/8/9/10/11 的专属分支与 1.23.10 的测试模式片段（`_extract_test_mode_content` 等）。
- 对拍断言：同一帧 → Web 摘要 == 桌面摘要（逐字），含协议10/11 的 MMDTYPE/NID/TEI/msduSeq 口径。

### R2 前缀剥离对齐

- 采用共享核心的完整实现（跨行引号状态机、`mac_only` 直通、EDA5、app 扫描阈值），Web 的 `strip_*` 复刻删除。
  - **P0 已完成部分**：`mac_only` 直通（Web `strip_csg_new_gen_prefix` 与桌面 `main_gui.py:4942` 同口径）与批量「不静默裁剪奇数长度」；剩余为跨行引号状态机、EDA5（协议10/11）、app 扫描阈值。
- 剥离过程**统计丢弃行数与原因**并在 message 中显示（消除「贴了 500 行只出 3 帧」的黑箱），桌面可选同步。

### R3 帧提取返回结构 + 行号

- Web 提取改用共享核心返回结构（含 `src_line`、`ed_data_type`），逐帧记录行号。
- 新增「定位原始日志」：批量摘要行点击 → 在批量输入框选中/滚动到对应行（对行式协议 3/5/9/10/11 与通用；流式扫描协议 0/1/2/4/7/8 不记录，与桌面一致）。
- 可选（若成本可控）：把桌面 `batch_source_view` 的「不可变原文快照 + 归一化 hex 流定位」逻辑抽为无 Qt 纯函数并在 Web 复用，用于输入被预处理覆盖后的回看。

### R4 ED 逐帧分支与摘要前缀

- 协议9 逐帧：ED 提取失败 → 明确失败行 + 摘要「ED 帧解析失败…」；合法 ED 无业务数据 → 输出监控头 + `[ED:类型] 包装名` 摘要（与桌面 `7479-7541` 同口径）。

### R5b 结果搜索/筛选（本轮交付，1.23.12）

- 摘要卡片新增搜索框（关键词匹配 **摘要 / 协议类型 / 帧 HEX / #序号**，大小写不敏感）与状态下拉（全部/成功/失败/异常）——口径同桌面 `_on_batch_filter_changed`（`main_gui.py:9876`：摘要+类型+原始HEX / 状态）。
- 过滤作用于**全量**摘要（不限当前页）后接分页：过滤后回第 1 页、页数与行号照旧；有关键词或筛选时显示 `显示 N / M`；选中帧被过滤掉时清空右侧详情（桌面同行为：自动改选第一条可见行，此处改为清空选中，避免误指）。
- 帧 HEX 只存在后端私有摘要行（`_batch_summaries[i]["hex"]`），切片下发前剔除 → 前端载荷与改造前一致。
- 纯函数 `web_utils.filter_batch_summaries` + `BATCH_STATUS_FILTERS`；`test/test_web_batch_paging.py` 57 项覆盖。

### R5 诊断与状态字面量

- 空输入/无帧：报文补「清洗后样本（前 200 字符）+ 当前协议名 + 可能原因」。
- 异常状态统一为 `异常`（保留原始异常串字段），与桌面一致。

### R6 类型列与导出

- 摘要与类型分列：类型列用共享核心的类型名函数（`_get_frame_type_name` 等价），不再与摘要同文。
- 导出：CSV 补字段详情（或提供 Excel 导出，复用 `enhanced_export.py`）；导出走流式/分块，避免整串 `rx.download` 复制（与 `web-parse-perf` 协调，本任务只保证字段完整性）。
- 显示上限提示明确化：说明「仅显示前 300 条，导出包含全部」。

## Acceptance Criteria

1. `test/test_web_batch_alignment.py`（新增，登记 `CORE_TESTS`）覆盖：摘要逐字对拍（协议0/7/8/9/10/11）、跨行 `fc_payload_data` 日志提取条数与内容、EDA5 剥离、丢弃行统计、ED 逐帧三分支、行号定位（纯函数级）、异常状态字面量、CSV 字段详情。
2. 真实现场日志（仓库内 `国网新一代协议/HDC-国网双模协议/TMI模式遍历测试_频段1__All.log` 或等价样本）在 Web 与桌面得到相同帧数与相同摘要集合。
3. `python release_check.py` 无 FAIL。
4. `AGENTS.md §7` 测试清单与 `CHANGELOG` 同步。

## Out of Scope

- 单帧链路的字节高亮/深度解析（子任务 `web-single-frame-alignment`）。
- 数据库/服务端持久化批量结果。
- 桌面的时序图、快照查看器等桌面专属 UI 的 Web 移植（仅复用其纯逻辑，若有）。

## Risks / Deferred

- 行号定位依赖提取器的行映射，需与共享核心的返回结构一起定型；若共享核心先落地，本任务只做消费。
- 大文件（≥10k 帧）下前端仍只显示 300 条：分页/虚拟滚动留待确认需求后跟进。
