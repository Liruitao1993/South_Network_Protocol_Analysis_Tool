# PRD: 修正 0x0006/0007/0008 扩展命令 3 字节偏移错误

## Goal

修复 0x0006、0x0007、0x0008 三个扩展命令的解析偏移错误：旧代码沿用国网格式假设，从 data[3] 开始读字段，实际通感一体版文档中"字节3"就是扩展数据的第 1 字节（data[0]）。

## Background

- 2.0 测试扩展命令的字节编号基准：字节 0 = 文件长度(报文头长度)，字节 1-2 = 扩展ID，字节 3+ = 数据域。
- data 参数是去掉协议版本号、文件长度、扩展ID之后的纯扩展数据，即 data[0] = 文档字节 3。
- 0x0005 已按此规则修复。0x0006/0007/0008 有同样问题。
- 0x0006 (MAC层OFDMA配置): Table 7 — 字节 3 bit0 = OFDMA类型，bit1-3 = 调度节点数，bit4-7 = 保留。当前从 data[3] 读 → 错位 3 字节。
- 0x0007 (非组网场景TEI配置): Table 8 — 字节 3-4 = TEI(12bit) + 保留(4bit)。当前从 data[3] 读 → 错位 3 字节。
- 0x0008 (业务报文Bitloading收发开关): Table 9 — 字节 3 bit0 = 开关，bit1-7 = 保留。当前从 data[3] 读 → 错位 3 字节。

## Requirements

1. **0x0006**: 从 data[0] 解析 OFDMA类型(1bit) + 调度节点数(3bit) + 保留(4bit)
2. **0x0007**: 从 data[0] 解析 TEI(12bit, 小端 — 低8位data[0] + 高4位data[1]低4位) + 保留(4bit, data[1]高4位)
3. **0x0008**: 从 data[0] 解析 Bitloading开关(1bit) + 保留(7bit)
4. 数据不足时友好提示，不崩溃

## Acceptance Criteria

- [x] 0x0006 字段从 data[0] 读取，不再有3字节前置偏移
- [x] 0x0007 TEI 从 data[0] 读取，12位小端格式正确
- [x] 0x0008 开关从 data[0].bit0 读取
- [x] 现有 test_csg_new_gen.py 全部通过
- [x] 其他扩展ID不受影响

## Out of Scope

- 不修改 0x0001~0x0005
- 不新增字段或深度解析（0x0006只修正偏移，不扩展eFC等解析）
