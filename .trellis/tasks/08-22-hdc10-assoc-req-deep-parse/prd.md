# fix(hdc10): MAC头TEI字节序 + 关联请求表60深度解析

## 背景

真实 HDC 1.0（协议索引11）`pb_only` 报文解析暴露两处缺陷：

1. 标准 MAC 帧头（表4）原始源/目的 TEI 按大端拼接，与协议"HDC1.0 多字节字段全小端"约定不符。报文 MAC 头字节 `01 00` 被解析成目的 TEI=16，实际应为 1。
2. 关联请求报文（MMTYPE 0x0000，表60）仅解析站点 MAC(6B)+候选代理×5(10B)，固定头后 72 字节整体落到"其他信息/厂商扩展"，未按表60逐字段解析。其中版本信息字（表66）的厂商代码、芯片代码为 2 字节小端 ASCII，被按物理字节序直读（`48 4C`→"HL"），实际应为 "LH"。

## Requirements

- `hdc10_parser.py` `_parse_mac_std_header`：
  - 原始源 TEI = `(b0>>4)&0xF | b1<<4`
  - 原始目的 TEI = `b2 | (b3&0xF)<<8`
- `hdc10_mme_parser.py` `_parse_associate_req`：按表60完整解析固定头及后续字段，72 字节不得落入未解析"厂商扩展"：
  - 字节16 相线（主2b + 备选1 2b + 备选2 2b + 保留2b，表62）
  - 字节17 设备类型（表63）、字节18 MAC地址类型（表64）、字节19 模块类型低2b（表65）
  - 字节20-23 站点关联随机数（4B 小端）
  - 字节24-41 厂家自定义信息（18B，原样+ASCII提示）
  - 字节42-51 站点版本信息（10B，表66，子字段见下）
  - 字节52-53 硬复位累积次数、字节54-55 软复位累积次数（各2B 小端）
  - 字节56 代理类型（表69）、字节57-59 保留
  - 字节60-63 端到端序列号（4B 小端）
  - 字节64-87 管理ID信息（24B）
- 版本信息字 `_parse_version_info`：
  - 启动原因（表67）、BOOT版本、软件版本号（2B BCD）、版本时间（表68：年7b/月4b/日5b）
  - 厂商代码、芯片代码：2 字节**小端**拼 16 位后高字节在前显示（`48 4C`→"LH"、`30 39`→"90"）

## Acceptance Criteria

- [x] 回归报文 MAC 头：原始源 TEI=0、原始目的 TEI=1
- [x] 关联请求 88B 报文体逐字段解析，无"其他信息/厂商扩展"兜底行；字段偏移与表60一致
- [x] 版本信息：厂商代码 "LH"、芯片代码 "90"；软件版本 BCD、版本时间按表68位域解码
- [x] MME 头按 MMTYPE(2B LE)+保留(2B)=4B 处理，关联请求体 88B + 头 4B = 92B 与 MAC 头 MSDU长度一致
- [x] ICV 仍校验正确（未破坏帧切分）

## 涉及文件

- `hdc10_parser.py:1703,1713` — MAC 头 TEI 字节序
- `hdc10_mme_parser.py:160` — `_parse_associate_req` 重写 + 新增 `_parse_version_info` 及常量映射

## 避坑经验

HDC 1.0 所有多字节字段小端，含 12bit 跨字节 TEI 和 2 字节 ASCII 码（厂商/芯片代码）；仅 MAC 地址（6B）大端。已写入跨会话 memory `hdc10-little-endian-all-multibyte`。
