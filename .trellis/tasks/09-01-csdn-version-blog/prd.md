# CSDN 版本技术博客（每版本一篇，MD 导入发表）

## Goal

软件每完成一个版本更新，产出一篇**技术深度风**的 CSDN 博客文章（Markdown 存项目 `blog/` 目录），用户手动导入 CSDN 编辑器发表（1 分钟）。不自动发表（CSDN 无官方 API，浏览器自动化有风控风险，用户已确认放弃）。

## Requirements

- **触发时机**：每个版本完成提交后（feat / fix 批次均可，以 CHANGELOG 条目为单位）。无版本的日子不写。
- **产出物**：`blog/2026-09-01-v1.20.0-<slug>.md` 一篇（含 front-matter：标题/标签/分类建议）。
- **风格（技术深度风）**：面向开发者——
  - 版本功能亮点（2~3 个，讲清"解决了什么问题"）
  - 精选 1~2 个技术点深挖：实现方案、关键代码片段、踩坑记录（如 Reflex 跨 State 陷阱、SQLModel 旧库迁移、PySide6 QHttpMultiPart 上传）
  - 结尾附版本下载/源码链接占位 + 协议解析工具简介
- **素材来源**：`main_gui.py:CHANGELOG` 对应版本条目 + 任务 `.trellis/tasks/*/design.md` 技术细节 + 实际代码。
- **文章长度**：1500~3000 字，代码块可运行/真实，不灌水。

## Acceptance Criteria

- [ ] `blog/` 目录建立，含 `_TEMPLATE.md` 写作模板与 README（流程说明）
- [ ] 首篇文章 `2026-09-01-v1.20.0-gui-feedback-api.md` 产出，内容覆盖 GUI 反馈对话框 + Web API + 共享数据库三大块，技术点深挖 ≥2 个
- [ ] 文章中代码片段与实际代码一致（不虚构 API）
- [ ] 用户可直接复制全文到 CSDN「导入 Markdown」发表
- [ ] 流程固化：写入 AGENTS.md §9（每版本完成后同步写博客）与本文档，未来会话可复现

## Constraints

- 不自动发表；不使用浏览器自动化。
- 文章中不出现内部路径细节（.trellis/、pi 工具链等），以通用技术叙事呈现。
- 标题避免夸大（不用"吊打/最强"），符合 CSDN 社区规范。
