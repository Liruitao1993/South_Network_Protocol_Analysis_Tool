# TCP 监控：原始载荷成帧 + APDU 解析显示 + UI 完善

## Goal

TCP 监控目前只能处理 `ED..EE` 监控封装帧：纯 TCP 载荷既不产生「应用层帧」，也无法解析显示（实测 27 字节原始载荷 → 切出 0 帧、字节被静默丢弃）。本次把 TCP 监控补到「Wireshark 可用」的程度：

- 载荷里是已知协议报文 → 按协议解析并展示字段；
- 载荷是原始数据 / 未知协议 → **当成 APDU 正常显示**（Wireshark 风格字节视图 + 字段行），而不是「无法识别协议」+ 空表；
- 补齐解析结果视图、原始字节视图、帧表信息、协议过滤与切换重解析等 UI 能力。

用户价值：现场排查时不再出现「抓到了包但界面一片空白」，且无需切到 Wireshark 就能看清 TCP 载荷内容。

## Background（已确认事实）

- **F1 切帧只认 `ED..EE`**：`monitor/tcp_monitor.py:179` `FlowBuffer._deframe()` 扫不到 `0xED` 就逐字节前移。实测：27B 原始载荷 → 切出 0 帧、`pending_bytes` 残留 0（字节被静默丢弃）；混合（原始段 + ED 帧）只切出 1 帧，原始段被跳过。
- **F2 解析候选只有 3 个协议**：`monitor/tcp_monitor.py:1125-1144` 仅 南网新一代 / 国网新一代 / HDC 1.0；其它一律 `("未知", "无法识别协议", [])`（`monitor/tcp_monitor.py:1226`）。
- **F3 协议下拉只有 4 项**：`monitor/tcp_monitor.py:554`（自动识别 / 国网新一代 / 南网新一代 / HDC 1.0）。
- **F4 切换协议不重解析**：`monitor/tcp_monitor.py` 全文无 `proto_combo.currentIndexChanged` 连接；已抓帧保持旧解析，只有新帧才用新协议。
- **F5 原始字节视图弱**：`monitor/tcp_monitor.py:707-712` 的 `segment_hex` 是 120px 高 `QTextEdit`，无偏移列 / ASCII 列 / 字节高亮。
- **F6 统一解析入口已存在且与 GUI 解耦**：`protocol_registry.build_gui_parser(index, get_parser(spec.parser_key))` 对全部协议返回带 `parse_to_table(payload)` 的对象（实测协议 0/2/3/4/5/6/7/8 全部可用，覆盖 DLMS Wrapper / DLMS-APDU / 698.45 等 APDU 形态）。
- **F7 统一校验引擎已存在**：`validator.BaseValidator.verify(frame_bytes) -> ValidationResult`（`pass_count` / `fail_count` / `warn_count`），可作为自动识别的证据判据。
- **F8 字段树构建器已存在**：`parse_result_view.build_tree_from_table_data()` / `build_ui_tree()`（主窗口 1.23.25~1.23.28 已用），TCP 监控未复用。
- **F9 既有契约不得破坏**：ED..EE 解包路径、`mac_only`/`pb_only` 输入契约、HDC 自动识别只用 CRC-24 自证（`monitor/tcp_monitor.py:87-115`、`1147-1161`）；`FlowBuffer()` 无参构造、`_parse_and_summarize(frame)` 三返回值签名、协议下拉项名称（`findText("HDC 1.0")` / `findText("南网新一代")` 等）均被既有测试引用（`test/test_tcp_monitor_ed_hdc.py:115,143-146,181`、`test/test_tcp_monitor_proto11_frames.py:181,228`）。

## Key Decisions（已与用户确认）

1. **范围**：Block 1+2+3 —— 核心修复（切帧兜底 + APDU 显示）+ UI 完善；pcap 导入共用切帧留待后续独立任务。
2. **原始数据成帧粒度**：按 **TCP segment 逐包**（一个 TCP 报文 = 一行），最接近 Wireshark 包列表；不新增「成帧方式」下拉。
3. **协议识别范围**：**显式选择优先**；自动识别扩展到 TCP 相关协议（698.45 APDU / DLMS Wrapper 裸报文 / DLMS-APDU 裸报文 / 南网 / 国网 / 645），并沿用「证据判据」经验，避免解析器「退化结果却算成功」式误判。
4. **流程**：走 Trellis 任务流程（本任务 `09-21-tcp-monitor-raw-apdu`）。

## Requirements

### R1 原始载荷成帧（按 TCP segment）

非 ED 封装的 TCP 载荷必须成为可点击的「应用层帧」行：一个 TCP segment = 一行，长度 = 该报文载荷长度。

- AC1.1 对不含 `ED..EE` 的方向，连续发送 N 个带载荷的 TCP 报文 → 「应用层帧」出现 N 行，每行长度等于对应报文的载荷长度。
- AC1.2 含 `ED..EE` 封装的方向行为不变：仍按 ED 帧成帧，帧数与帧长与改动前一致，不额外产生原始行。
- AC1.3 同一批字节不会同时产出「ED 帧」与「原始载荷帧」（无重复计数、无重复显示）。
- AC1.4 空载荷报文（纯 ACK）不产生帧行。

### R2 协议识别范围扩展

- AC2.1 协议下拉在保留既有 4 项名称的前提下扩展，至少包含：自动识别、南网协议、DLMS Wrapper 裸报文、DLMS-APDU 裸报文、DLT645-2007、国网协议、698.45协议、国网新一代、南网新一代、HDC 1.0（显示名与注册表一致）。
- AC2.2 显式选择某协议时该协议优先；只有它解析失败才回落到「原始数据」行。
- AC2.3 自动识别对**结构可判别**的形态能选对协议：DLMS Wrapper、DLMS-APDU 裸报文、DLT645-2007 各至少 1 例实测命中；判据必须含**独立证据**（字节结构前置检查 + 解析器字段签名 + 校验器失败数择优），不得只凭「解析器返回非空」。
- AC2.3b **已声明的边界（校准实测得出）**：698.45 / 南网 / 国网 三者同为 `0x68` 起头、链路层结构相近，且校准实测表明校验器不具备跨协议判别力（南网样本对南网/国网校验器均为 0 fail；Wrapper/APDU 校验器对非自身帧形报 4 fail），故这三者的自动识别为**尽力而为**（字段签名 + 校验器失败数择优），**不保证判别，推荐显式选择**。该边界必须在测试中钉住（对齐既有 HDC MAC 帧「自动识别不覆盖」的边界声明做法）。
- AC2.4 不回归：既有 ED/HDC/南网新一代/国网新一代 样本判定与改动前一致（`test/test_tcp_monitor_ed_hdc.py`、`test/test_tcp_monitor_proto11_frames.py` 全绿）。

### R3 原始数据兜底显示（APDU 正常显示）

- AC3.1 未识别帧的「协议」列显示「原始数据」，「摘要」列至少包含载荷长度。
- AC3.2 未识别帧的「解析结果」非空：至少给出 长度 / 偏移 / 首字节 等原始行；若首字节命中 698.45 或 DLMS 的 APDU 标签表，摘要给出疑似协议与 APDU 名称（如「疑似 698.45 APDU: 链路请求」）。
- AC3.3 任意二进制载荷（含非 ASCII、含 `0x00`、含 `0xED`）都能显示且不抛异常。

### R4 Wireshark 风格字节视图

- AC4.1 每行 16 字节，显示 `偏移 | 16 个 hex 字节 | ASCII`，不可打印字符以 `.` 表示。
- AC4.2 在「解析结果」选中字段行 → 字节视图对应字节范围高亮；切换字段行高亮随之更新。
- AC4.3 选中某帧 / 某 segment 时，视图内容对应其字节，且显示长度与帧表 / segment 表长度一致。
- AC4.4 对 0 字节与 ≥4096B 载荷不崩、不卡死。

### R5 解析结果 表 / 字段树 切换

- AC5.1 「解析结果」Tab 提供「表 / 字段树」切换，字段树与主窗口同构（层级可展开、叶子显示解析值、说明进 tooltip）。
- AC5.2 切换视图不丢数据：同一帧在两种视图下字段数一致。
- AC5.3 字段树节点选中同样触发 AC4.2 的字节高亮。

### R6 帧表信息完善

- AC6.1 帧表新增「源 → 目的」列（`IP:端口`，按方向推导）。
- AC6.2 未识别帧以「原始数据」显式成行并以灰色弱化，不是空白行或跳过。
- AC6.3 列宽/字体与既有表一致，保留右键复制菜单与 Ctrl+滚轮缩放。

### R7 切换协议重解析

- AC7.1 切换协议下拉后，当前流已抓帧的 协议 / 摘要 / 解析结果 按新协议重算，帧表与 `_frame_cache` 同步。
- AC7.2 重解析不改变帧的数量、顺序与字节内容。
- AC7.3 1000 帧样本下重解析不长时间阻塞 UI（分批或后台）。

### R8 过滤与空状态

- AC8.1 工具栏提供「仅显示未识别」勾选与协议过滤；过滤只影响显示，不清空缓存。
- AC8.2 取消过滤后恢复全部行。
- AC8.3 某方向只有原始数据时，界面给出明确可理解的呈现（不出现空白列表）。

## Out of Scope

- **Block 4**：pcap 导入（`pcap_import.py`）与 TCP 监控共用切帧/解析逻辑 —— 另立任务。
- TCP 乱序重组、重传去重、序号/标志位/窗口等逐包元数据 —— 保持现状（按到达顺序拼接载荷）。
- ED..EE 解包语义、HDC 自动识别判据的改动（F9 契约）。
- 主窗口单帧解析界面的字节高亮迁移到新字节视图组件（本次只新增组件并在 TCP 监控使用）。
- Web 版 TCP 监控（不存在该功能）。
