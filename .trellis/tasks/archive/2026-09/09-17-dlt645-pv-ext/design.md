# Design — 协议6 光伏协议转换单元 645 扩展协议解析

## 1. 改动边界

| 文件 | 改动性质 |
| --- | --- |
| `dlt645_pv_ext.py`（**新增**） | 扩展 DI 表 + 数据块深度解码；纯逻辑无 Qt；对外契约与 `lme_info_entry_parser.parse_lme_dlt645` 对齐 |
| `dlt645_parser.py` | ① DI 表加载时合并扩展表；② 新增扩展 DI 深度解析分派；③ `0FH`/`8FH` 透传帧数据域呈现 |
| `dlt645_data_codec.py` | `FUNC_NAMES[0x0F]`（`0x8F` 走 DIR=1 + FUNC=0x0F，复用同条目） |
| `dlt645_di_lookup.py` | 查询页数据源合并扩展表（与解析器共用同一函数） |
| `reflex_web/reflex_web/lookup_utils.py` / `web_utils.py` | Web 查询页数据源 + 645 呈现路径同步（按实测确认是否需要改转表逻辑） |
| `test/test_dlt645_pv_ext.py`（**新增**） | 覆盖验收 A1~A10 与变异反证 |
| `release_check.py` | 登记新套件进 `CORE_TESTS` |

不改：`dlt645_di.json`（生成物，AGENTS.md §4.5 禁止手改）、`dlt645_frame_gen.py` / `dlt645_frame_schema.py`（组帧，范围外）、`dlt645_sim/`（虚拟表，范围外）。

## 2. 现状数据流（与扩展点的关系）

```
DLT645Parser.parse(data)
  ├─ check_frame / 数据域减 0x33
  ├─ DI_MAP = _load_di_map()                     ← ① 在此合并扩展表
  ├─ di_code = data[0:4] 小端 → "02E60101" 形式
  ├─ 控制码解码（D7 方向 / D0~D4 功能码 / D6 异常）  ← ③ 0x0F 需在此可识别
  ├─ LME 深度解析：di_code in _LME_DI_CODES → parse_lme_dlt645(di, ctrl, data) → rows
  └─ fields 组装：
        ├─ lme_rows 非空 → 逐行展开                          ← ② 增加 pv_rows 分支（同契约）
        ├─ DIR=1 且 func ∈ {0x11,0x12} → decode_value（单值）
        ├─ DIR=0 且 func=0x14 → 写请求（DI+密码+操作者+数据）
        ├─ func=0x18 改密码 / 0x1A·0x1B 清零 / 0x13·0x15 地址 / 0x08 校时 / D6=1 ERR
        └─ 其他 → 数据内容原始 hex
```

**关键约束**：现有 `decode_value` 只解**单个**值，而扩展 DI 绝大多数是**多值数据块**（3~18 个值、含时刻与枚举）。因此扩展走 `lme_rows` 那条**行列表**通路，而不是 `decode_value`。

## 3. 设计决策

### D1 新模块 `dlt645_pv_ext.py`（纯逻辑，契约镜像 LME）

```python
PV_DI_MAP: dict[str, dict]
#   8 位 HEX DI（小端解析后的写法，如 "02E60101"） → {"name","unit","data_type","length","group"}
#   group ∈ {"变量","参数","事件"}，用于呈现与断言

def merge_pv_di_map(base: dict) -> dict
#   返回 base 的浅拷贝并入 PV_DI_MAP；**同名键冲突时保留 base**（不覆盖既有 645 标准 DI），
#   并把冲突键记入模块级 `_merge_conflicts`（供测试断言为空）

def is_pv_di(di_code: str) -> bool
def parse_pv_di(di_code: str, ctrl: int, data: bytes) -> tuple[Optional[list[tuple]], str]
#   返回 (rows, 业务名)；rows 行格式 (字段, 原始值hex, 解析值, 说明) —— 与 parse_lme_dlt645 完全一致；
#   非扩展 DI 返回 (None, "")
```

**为什么新模块而不是扩 `dlt645_di.json`**：① 该 JSON 是生成物（AGENTS.md §4.5 明令勿手改）；② 扩展协议是**另一份规范**（光伏协议转换单元），与 645-2007 + 国网补遗 的生成流程不同源；③ 与 LME 的既有做法一致（`lme_info_entry_parser.py` 独立成模块，解析器按 DI 分派）。

### D2 DI 表单一来源与合并点

- `DLT645Parser._load_di_map()`：读 JSON 后 `return merge_pv_di_map(data.get('di_map', {}))`
- `dlt645_di_lookup.py` 与 Web `lookup_utils.py`：同样调用 `merge_pv_di_map`
- **三处调用同一函数** ⇒ 名称/单位/格式只有一个定义处（满足 R5）。合并函数幂等（重复调用结果相同）。

### D3 分派点（`dlt645_parser.py`）

在 LME 分派之后新增（两者 DI 集合不相交，顺序不影响结果，但显式并列便于阅读）：

```python
pv_rows = None
pv_name = ""
if is_pv_di(result['di_code']):
    pv_rows, pv_name = parse_pv_di(result['di_code'], ctrl, result['data'])
    if pv_name:
        result['di_desc'] = pv_name
```

`fields` 组装处，在 `lme_rows is not None` 分支旁增 `pv_rows is not None` 分支（两条都展开行列表 + 附「数据内容(原始)」备查行）。

### D4 控制码 `0FH` / `8FH`（无线转发透传）

- `dlt645_data_codec.FUNC_NAMES[0x0F] = "无线转发(透传)"`；`0x8F` 因 `func = ctrl & 0x1F = 0x0F` 自动得到「无线转发(透传)应答」。
- 数据域解析：`DI(4B) + 透传数据(N)`，`L = 04H + N`（文档 I.3.3.1）。
- **必须新增 `func == 0x0F` 分支**：现有「读数据应答」只在 `func ∈ {0x11,0x12}` 生效，透传帧不会误入；但若不加分支会落到兜底「数据内容」行，故显式呈现：
  - 行1 `透传数据标识 DI`：DI 码 + 名称（命中扩展/标准表则显示名称，否则「未知数据标识」）
  - 行2 `透传数据`：hex + 长度；**若 DI 命中扩展表，继续调用 `parse_pv_di` 展开**（透传内容即扩展协议的 DI 数据块，这是本协议的实际用法）

### D5 数据块解码规则（核心算法，必须逐条按文档核对）

1. **切分权威 = 「数据长度」列**（非「数据格式」列）：该列把**每个值的字节数直接相连**，如 `222`=三个值各 2 字节；全变量块 `222333444444442222` = 3×2B + 3×3B + 4×4B + 4×4B + 4×2B = 18 值（与文档该行列出的 18 个数据项一一对应，已人工核对）。总和 ≠ 实际 body 长度时：标注「声明 X 字节 / 实际 Y 字节」并尽力解析（AGENTS.md 陷阱 23）。
2. **每值解码**：645 规则（数据域已减 `0x33`，多字节 BCD **低字节在前**）；整字节 `FF` = 该项不存在 → 显示 `FF(无此项)`（单相设备 B/C 相即此情形）。
3. **功率符号位**（`02E603xx`/`02E604xx`，4 字节/值）：文档「最高比特用 0/1 表示正负——0 为正表示逆变器发电，1 为负表示逆变器用电；如最高 X 为 0111 表示 +7，X 为 1111 表示 -7」，范围 `[-7999.9999, 7999.9999]`。**实现时必须用文档示例构造 golden 用例确定「最高比特」落在哪个字节/半字节**（低字节在前 ⇒ 通常是值最高字节的最高位），不得凭猜。
4. **事件块**（`03E6xxxx` 记录类）：按长度列切为「发生时刻 6B + 结束时刻 6B + [按逆变器的若干 12B/1B/…]」；**逆变器字节序：从左往右 = 逆变器 12、11、…、1**，呈现时须标注该映射（建议一行汇总 12 个值 + 逐项「逆变器N」行）。
5. **调控结果枚举**：`00` 调控成功 / `01` 未调 / `02` 调控失败 / `03` 调控不支持 / `04` 其他问题 / `FF` 不存在。
6. **`DI0` 语义按组区分**：变量类与参数类 = 逆变器序号（`01`~`0C` → 逆变器 1~12，`FF` = 下挂所有）；事件记录类 = 第 N 次记录（`01`~`32` → 第 1~50 次，`0x32`=50）。名称行须体现（如「光伏逆变器3的电压数据块」「（上50次）开关机控制事件数据块」）。
7. **存疑不臆造**：文档个别行字节切分有歧义（`04E60001` 长度 16 的「数量 M + 12 路通信地址」、`03E61401` 的 `36464` 重复段、`04E60001` 的 `13221` 档案切法）→ 按该行**文字描述**切分并在代码注释标注依据；仍无法确定的按「保留原始 hex + 标注存疑」呈现。

### D6 两端同步（R6）

- 查询页：`dlt645_di_lookup.py` 与 Web `lookup_utils.py` 均走 `merge_pv_di_map`。
- 解析呈现：Web 的 645 路径（`web_utils.py:610` 附近按行分割每帧）复用同一 `DLT645Parser`，扩展行会自然流过；**必须实测确认**（若 Web 对 645 有独立的转表/摘要白名单逻辑，需同步，并加对拍断言 —— 陷阱 31 记录过这类漂移）。

### D7 测试策略

- 新套件 `test/test_dlt645_pv_ext.py`（含 `import _path_setup  # noqa: E402,F401`）：
  - **表驱动全覆盖**：遍历 `PV_DI_MAP` 每个 key，断言 `parse_pv_di` 均返回非空 rows（防漏项，R-4）
  - golden：电压块 A/B/C、电流块、功率（正/负/边界）、功率因数块、全变量块 18 值
  - 单相 `FF`、`DI0=FF`（下挂全部）、事件块逆变器字节序、调控结果枚举、`03E60132`=第 50 次
  - `0FH`/`8FH` 透传帧（含透传内容命中扩展 DI 的二次展开）
  - 兜底不回归：未知 DI / 未知控制码 / 既有标准 DI 行为不变
  - 两端对拍（桌面 vs Web 关键字段）
  - **变异反证**（A12）四条，要求实际观察到变红
- 帧构造：优先用现有 `DLT645FrameGenerator`（`dlt645_frame_gen.py`）拼帧 + 减 0x33 编码；若组帧器不支持扩展 DI（范围外），则在测试内手工拼字节（不影响产品代码）。

## 4. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| R-1 文档字节切分歧义（`04E60001`/`03E61401` 等） | 按文字描述切分 + 代码注释标注依据 + 存疑处保留 hex 并标注；不得臆造（陷阱 23 精神：不空白、不造假） |
| R-2 功率符号位与 BCD 的交互理解偏差 | 用文档示例（`0111`=+7、`1111`=-7）构造 golden 先验证算法，再落地 |
| R-3 Web 侧 645 转表路径与桌面不一致（陷阱 31） | 先实测 Web 呈现；不一致则两端同改 + 对拍断言 |
| R-4 扩展 DI 下标组合多，易漏项 | 表驱动全覆盖断言（遍历 `PV_DI_MAP`） |
| R-5 跨帧状态（陷阱 41） | 新模块为纯函数，不使用实例状态；如需缓存则每帧重置 |
| R-6 与既有 1099 条标准 DI 撞键 | `merge_pv_di_map` 冲突时保留 base + 记录冲突；测试断言冲突集为空 |

## 5. 回滚

新增模块 + `dlt645_parser.py` 少量分派 + `FUNC_NAMES` 一行 + 两处查询页数据源合并；无数据迁移、无接口变更。回滚 = `git revert <commit>`（新模块删除后解析器回到既有 1099 条 DI 行为）。
