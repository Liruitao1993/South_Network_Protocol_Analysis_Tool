# 645虚拟表 LME 模块版本查询下发

## Goal

「645虚拟表」目前只做从站：主站发来的 11H/13H/15H/08H 由引擎应答，其余功能码回 D1H 异常；串口线程收到 DIR=1 的从站帧一律「非主站帧，忽略」。因此**虚拟表无法主动向模块索取信息**。

本任务让虚拟表以 **645 主站**身份，按《LME产品相关信息生产运维接口手册_V2.4_251115》§4.2 / §4.6 / §4.7 组好 LME 自定义帧下发到串口，读取 HPLC 模块的**版本信息与 LME 扩展内部版本信息**，并把模块回包用既有 LME 深度解析展示出来。

## Requirements

### R1 LME 帧构造（纯逻辑，无 Qt）— 新增 `dlt645_sim/lme_query.py`
- `build_single_sta_query(addr="AAAAAAAAAAAA") -> bytes`：4.2，`C=11H`，数据域仅 DI（`04FFAAF9` 线上 `2C DD 32 37`），L=04H。
- `build_dual_query(addr, entries) -> bytes`：4.6，`C=11H`，数据域 = DI(`01 DD 00 FF`) + `0x00`(条目信息) + `M` + M×2B 请求头；`entries` 为 `[(分类, 数据ID)]` 或 `"分类/数据ID"` 串，空 → M=0 读模块全部支持条目。复用 `pack_lme_query_request`。
- `build_dual_set(addr, items) -> bytes`：4.7，`C=14H`，数据域 = DI + `0x00` + `M` + M×(`2B TLV 头` + L 字节数据)；`items` 为 `[(分类, 数据ID, 数据hex)]`。TLV 头的编码格式取 `LME_INFO_ENTRIES` 该条定义（1/2/3），长度取 hex 字节数；**长度 >31 报错**（5bit 上限）；条目不在字典中仍允许，编码按 BIN(2)。
- 全部经 `DLT645FrameGenerator.build_frame` 封装，保证与主站/解析器口径一致（+0x33、CS、地址低字节在前）。
- 校验：地址必须 12 位 hex；条目项格式错/分类超 7/数据ID 超 63/数据 hex 非法/长度>31 → 抛中文 `ValueError`（UI 弹提示，不发送）。

### R2 串口回包链路（`dlt645_meter_sim_widget.py`）
- `Dlt645SerialSlaveThread` 新增 `slave_frame = Signal(str)`（帧 hex）。run() 里：`ctrl & 0x80` 的帧不走引擎应答，emit `slave_frame` 并记日志「◀ 模块回包: …」；DIR=0 帧行为完全不变（引擎应答 + `frame_exchanged`）。
- 下发复用 `write_frame()`；未监听/写失败沿用现有提示与日志（`⇱ 已下发`）。

### R3 GUI（运行页新增「模块版本查询（LME 自定义下发）」分组）

**形态：三个常驻一键按钮 + 可审帧框**（已确认；不是下拉式两步）。

```
┌ 模块版本查询（LME 自定义下发） ─────────────────────────────────────────┐
│ 目标地址 [AAAAAAAAAAAA]                                                  │
│ [读模块版本(4.2)] [读内部详细信息(4.6)] [设置(4.7)]                        │
│ 条目 [0/15,1/3                        ]  ← 4.2 时隐藏并清空               │
│ 帧   [68 AA AA AA AA AA AA 68 11 04 …]  [下发到串口] [复制hex]（只读等宽） │
└──────────────────────────────────────────────────────────────────────────┘
```

- 三个按钮 = 三条固定请求：`读模块版本` → R1 4.2（无参数）；`读内部详细信息` → R1 4.6；`设置` → R1 4.7。按钮文案即功能名，不做查询类型下拉。
- 参数框只有一行「条目」，语义随按钮切换（tooltip 同步）：4.6 `分类/数据ID`（逗号分隔，**留空=读模块全部支持条目**）；4.7 `分类/数据ID:hex数据`（必填）；4.2 时隐藏并清空。
- **点按钮的行为**：组帧 → 写入只读帧框（等宽、NoWrap）→ 日志记 `控制码 C=11H 读数据 | L=04H | 数据域 …` → **若串口已监听则随即下发**（日志 `⇱ 已下发`）；**未监听不弹窗**，只记日志「已生成，串口未监听（可先『开始监听』或用『下发到串口』）」。
- `设置`(4.7) 例外：组帧后先 `QMessageBox.question` **列出条目（`分类c/数据d 名称`）确认**，确认才下发；取消则帧框保留、不下发。
- `下发到串口`：重发帧框当前内容（4.7 同样先确认）；未监听 → 沿用既有提示（先「开始监听」）；写失败 → 弹 critical + 日志。
- `复制hex`：复制帧框内容。
- 生成失败（地址非法/条目格式错/长度超 31）→ `QMessageBox.warning` 中文提示，**不覆盖已有帧框内容**、不写串口。
- 回包展示：`slave_frame` → `DLT645Parser.parse` → 复用 `_fill_resp_table` 填「最近响应帧解析」表（LME 字段逐行），日志加 `◀ 模块回包解析: 接口名`。
- 离线回包核对：在「离线模拟」区贴入 DIR=1 帧并点「生成响应」时，改为**直接解析展示**（日志「检测到从站回包，直接解析」+ 结果表），不再只给「忽略」。
- 与串口线程的连接用既有模式（`Signal` 跳回 GUI 线程），窗口关闭时 `shutdown()` 语义不变。

## Acceptance Criteria

1. 点「读模块版本(4.2)」生成的帧与手册示例**逐字节一致**（含地址 `AA×6`、`C=11H`、DI 线上 `2C DD 32 37`、`CS=0x53`）；串口未监听时只在日志留提示、不弹窗。
2. 串口监听中点「读内部详细信息(4.6)」（条目 `0/15`）→ 自动下发（日志 `⇱ 已下发`）；模块（或回环注入）回包自动解析进结果表，出现条目名与语义值（如 `BR_9600`）。
3. 4.7 帧数据域 = `DI + 00 + M + M×(2B TLV 头 + 数据)`，编码/长度取自条目定义；长度 >31 或条目格式非法时点按钮即报错、不写串口、帧框保留原内容、不崩。
4. 4.7 下发前出现确认框；取消后串口无写入（日志无 `⇱ 已下发`），帧框仍保留该帧。
5. 离线贴入 DIR=1 回包（手册 §5.1.1 接收帧，135B）→ 结果表展示 `外部版本号 V0102`、`MCU内部版本号 v0244` 等行且无「不完整」提示；日志含「检测到从站回包」。同一帧砍短后应出现 `⚠ 数据不完整`。
6. `python test/test_dlt645_sim_lme_query.py` 全过；`test/test_dlt645_sim.py`、`test/test_dlt645_lme.py`、`test/test_dlt645_frame_gen.py`、`test/test_dlt645_frame_gen_gui.py` 无回归。
7. AGENTS.md / CHANGELOG 已同步；`dlt645_frame_schema.py` 与 `dlt645_parser.py` 零改动（解析链路不回归）。

## Risks / Deferred

- **4.7 帧是否含 645 密码组**：docx 表（4.7 下行）与仓库解析侧都按"DI 之后直接是条目信息"实现，本次构造同口径。若实机模块要求标准写数据密码组（`DI + PA + P0P1P2 + C0~C3 + 数据`），需在 `build_dual_set` 增补前缀（解析侧 `parse_dual_entry_set_request` 会因 `data[4]==0` 判据失配需同步），先按文档口径实机验证后再定。
- **回包长度**：4.2 数据单元声明 251 字节，实测手册示例 123 字节即可完整解析（字段全部覆盖，**不报不完整**）；真被截断（字节不足）时解析器补 `⚠ 数据不完整` 行并尽力展示，两者都属预期。
- **目标地址默认 `AA×6`**：依手册 §5.1.1 示例（点对点测试底板上模块应答自带地址）；实机若需 STA 地址，由 UI 目标地址框覆盖。
- 本机虚拟串口对（COM1↔COM2）不可用时，端到端用例降级为跳过（其余用例仍为强断言）。
