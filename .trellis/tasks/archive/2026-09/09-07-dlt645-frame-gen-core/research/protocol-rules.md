## 1. 帧结构（7 个域）

来源：`DLT645-2007.md:424`（概述）、`DLT645-2007.md:436-480`（5.2 帧格式）

```
| 帧起始符 | 从站地址域 | 帧起始符 | 控制码 | 数据长度 | 数据域 | 校验码 | 结束符 |
|   68H    |  A0..A5    |   68H    |   C    |    L     |  DATA  |   CS   |  16H   |
|  1 byte  |  6 byte    |  1 byte  | 1 byte |  1 byte  | L byte | 1 byte | 1 byte |
```

固定开销 = 12 字节（起始 1 + 地址 6 + 起始 1 + C 1 + L 1 + CS 1 + 结束 1）。`dlt645_parser.py:34` `check_frame` 要求 `len >= 12`。

- **5.2.1 帧起始符**（`:437` 附近）：固定 `68H`，两处（data[0] 与 data[7]）。
- **5.2.4 数据长度 L**（`:466` 附近）：L 为数据域字节数；文档注明读操作 L ≤ 200，写操作 L ≤ 50；**L=0 表示无数据域**。
- **5.2.7 结束符**（`:480` 附近）：固定 `16H`。

## 2. 地址域（A0~A5）字节序与广播/缩位地址

来源：`DLT645-2007.md:449-459`（5.2.2 地址域）

- 地址域 6 字节，**BCD 编码**（每字节 2 位十进制）。
- **`DLT645-2007.md:459`「地址域传输时低字节在前」** → 组帧时地址需**逆序**发送（A0 是最低字节先发）。
- **`DLT645-2007.md:455` 广播地址 = `999999999999H`**（12 个 9），用于广播校时、广播冻结等（不要求应答）。
- **`DLT645-2007.md:457` 缩位寻址**：地址中 `AAH` 为通配符（任意），用于读/写通信地址命令（地址域填 `AAAAAAAAAAAA`）。

代码交叉验证：
- `dlt645_parser.py:68` 解析地址用 `data[1:7][::-1].hex()`（**逆序还原**），即帧内是低字节在前，解析后转成人类可读的高字节在前字符串。
- `test/test_dlt645_lme.py:31` `build_frame(addr=b"\x10\x00\x00\x25\x00\x00")` 注释「addr 为帧内地址字节（低字节在前）」。
- `test/test_dlt645_lme.py:276` 官方样例帧 `68 28000026 0526 ...`，应答解析出通信地址 `260526000028`（帧内 `28 00 00 26 05 26` 逆序）。

**组帧结论**：写地址域 = `bytes.fromhex(addr_str)[::-1]`（addr_str 为 12 位高字节在前 hex）。广播校时/冻结用 `bytes.fromhex("999999999999")[::-1]`（等价于全 0x99，逆序不变）；读/写通信地址用全 `0xAA`。

## 3. 控制码 C 位定义（⚠️ 文档为图片，结论由反推 + 代码验证）

### 缺口
`DLT645-2007.md` 的 **5.2.3 控制码** 小节是一张图片（OCR 占位 `img_in_image_box_175_452`），**md 文本中没有位定义表**。若需要权威位定义文本，须查 `DLT645-2007 多功能电表通信协议.pdf` 的 5.2.3 节。

### 反推依据（文档中各命令的请求/应答控制码取值）
| 命令 | 请求 C | 正常应答 C | 有后续帧应答 C | 异常应答 C |
|---|---|---|---|---|
| 读数据 | `11H` | `91H` | `B1H` | `D1H` |
| 读后续 | `12H` | `92H` | `B2H` | `D2H` |
| 写数据 | `14H` | `94H` | — | `D4H` |
| 广播校时 | `08H` | （不应答） | — | — |
| 冻结 | `16H` | `96H` | — | `D6H` |

从取值差异可精确分离各位：
- `0x11 → 0x91`：差 `0x80` → **bit7 = 从站应答标志 / DIR（0=主站发出请求，1=从站应答）**
- `0x91 → 0xB1`：再或 `0x20` → **bit5 = 后续帧标志（1=有后续数据帧）**
- `0x91 → 0xD1`：`0xD1 = 0x80|0x40|0x11` → **bit6 = 异常应答标志（1=异常/ERR）**
- 低 5 位 `0x11` 保持不变 → **bit0~bit4 = 功能码**

### 代码交叉验证（权威口径以代码为准）
`dlt645_parser.py:119-150`：
```python
ctrl & 0x80   # DIR / 从站应答标志（D7）
ctrl & 0x40   # 异常应答标志（D6）
ctrl & 0x20   # 后续帧标志（D5）
ctrl & 0x1F   # 功能码（D4~D0）
```
`lme_info_entry_parser.py:883-884`：`dir_bit = (ctrl >> 7) & 0x1`；`func = ctrl & 0x1F`。
`test/test_dlt645_lme.py:327-328` 注释「控制码 D1H = DIR1+D6+FUNC01」。

### 组帧结论（控制码构造公式）
```
C = (dir_bit << 7) | (err_bit << 6) | (more_frame_bit << 5) | (func_code & 0x1F)
```
- 组「请求帧」时 `dir_bit=0`、`err_bit=0`，`more_frame_bit` 一般为 0。
- **注意**：文档没有把 bit5/bit6 明确命名为「DIR」还是「PRM」。645-2007 与南网/698.45 的 DIR/PRM 语义**不同**（645 只有 DIR 方向位 + 功能码，无独立 PRM 启动位）。这是**需用户确认的口径问题**（见摘要）。

## 4. 完整功能码表（section 7，均含文本帧格式表）

来源：`DLT645-2007.md:556-1086`（第 7 章）。功能码 = 控制码低 5 位。

| 功能码 | 命令 | 请求 C | 应答 C | 数据长度 L | 数据域内容（减 0x33 后） | 文档行号 |
|---|---|---|---|---|---|---|
| `11H` | 读数据 | 11H | 91H/B1H（异常 D1H，ERR 1B） | 请求 L=04（仅 DI）；应答 L=04+m | DI0 DI1 DI2 DI3（+ 应答数据） | `:562` |
| `12H` | 读后续数据 | 12H | 92H/B2H（异常 D2H） | L=05 | DI0..DI3 + **SEQ 帧序号 1B**（1~255，请求从 1 起递增，应答与请求相同） | `:629` |
| `14H` | 写数据 | 14H | 94H（L=00，异常 D4H） | L=04+04+04+m | DI0..DI3 + **PA P0 P1 P2（密码权限+密码）** + **C0 C1 C2 C3（操作者代码）** + DATA | `:679`, `:683` |
| `13H` | 读通信地址 | 13H | 93H（L=06，数据域=A0..A5）；异常不应答 | 请求 L=00（地址域填 AA…AA） | 无（请求）；应答 6B 地址 | `:728` |
| `15H` | 写通信地址 | 15H | 95H（L=00）；异常不应答 | L=06（地址域填 AA…AA） | A0..A5（新地址，低字节在前） | `:758` |
| `08H` | 广播校时 | 08H | **不要求应答** | L=06 | 帧格式表 `:804` 线序 = **ss mm hh DD MM YY**（低字节在前）；文档正文写 YYMMDDhhmmss；±5min 内执行 | `:794`, `:804` |
| `16H` | 数据冻结 | 16H | 96H（异常 D6H） | L=04 | 帧格式 **mm hh DD MM**；`99DDhhmm`=月周期定时冻结，`9999hhmm`=日冻结，`999999mm`=时冻结，`99999999`=瞬时冻结；有广播冻结（地址 99H） | `:820` |
| `17H` | 更改通信速率 | 17H | 97H（Z 须相同，异常 D7H） | L=01 | **Z = 通信速率特征字**（各位不允许组合，仅 Bit0~Bit7 一位为 1 时有效） | `:872` |
| `18H` | 修改密码 | 18H | 98H（L=04 返回新密码，异常 D8H） | L=0C | DI0..DI3 + **PA0 P00 P10 P20（原密码组）** + **PAN P0N P1N P2N（新密码组）**；PA 范围 00~09，00 最高权限 | `:916` |
| `19H` | 最大需量清零 | 19H | 99H（异常 D9H） | L=08 | PA P0 P1 P2 + C0 C1 C2 C3 | `:964` |
| `1AH` | 电表清零 | 1AH | 9AH（异常 DAH） | L=08 | PA P0 P1 P2 + C0 C1 C2 C3 | `:1006` |
| `1BH` | 事件清零 | 1BH | 9BH（异常 DBH） | L=0C | 事件总清零 = PA0 P00 P10 P20 + C0C1C2C3 + **FFFFFFFF**；分项清零 = 密码 + 操作者 + 事件记录 DI（DI0 用 FF） | `:1048` |

> 密码权限级别 PA 说明（`:916` 附近）：00 最高权限；02 级 = 电表清零/事件清零；04 级 = 写数据/最大需量清零。

**代码交叉验证**：`dlt645_data_codec.py:97` `FUNC_NAMES` 已定义 0x08/0x11/0x12/0x13/0x14/0x15/0x16/0x17/0x18/0x19/0x1A/0x1B 全部 12 项中文名，与上表完全一致。

## 5. 数据域 +0x33 加扰规则

来源：`DLT645-2007.md:472`（5.2.5 数据域）：「发送方按字节加 33H，接收方减 33H」。

- **组帧（发送）**：真实数据域每字节 `(b + 0x33) & 0xFF`。
- **解析（接收）**：`(b - 0x33) & 0xFF`。

代码交叉验证：
- `dlt645_parser.py:84`/`:87`：`bytes([(b - 0x33) & 0xFF for b in ...])`（解析减 0x33）。
- `test/test_dlt645_lme.py:33`：`enc = bytes((b + 0x33) & 0xFF for b in decoded_data)`（组帧加 0x33）——**这是组帧加扰的权威参照**。

**加扰范围**：仅数据域 DATA（L 字节），不含地址/C/L/CS。加扰后再参与 CS 计算。

## 6. CS 校验码起止范围

来源：`DLT645-2007.md:476`（5.2.6 校验码）：「从第一个帧起始符开始，到校验码之前的所有各字节的模 256 的和」。

即 `CS = sum(帧起始符68H .. 数据域最后一字节) & 0xFF`，**包含**首尾两个 68H、地址域、C、L、加扰后 DATA；**不含** CS 本身与结束符 16H。

代码交叉验证：
- `dlt645_parser.py:34` `check_frame`：`cs = sum(data[0:-2]) & 0xFF`，与 `data[-2]` 比较（`data[-2]` 是 CS，`data[-1]` 是 0x16）。
- `test/test_dlt645_lme.py:34-36`：`body = 68 + addr + 68 + C + L + enc; cs = sum(body) & 0xFF; return body + [cs, 0x16]`——**组帧 CS 计算的权威参照**。

## 7. DI 数据标识 4 字节传输序

- DI（数据标识）4 字节，**传输时低字节在前**：DI0 DI1 DI2 DI3。
- 解析用 little-endian：`int.from_bytes(data[0:4], 'little')` → `%08X` 得到人类可读 DI 码。

代码交叉验证：
- `dlt645_parser.py:105`：DI = `data[0:4]`，little-endian 解析。
- `lme_info_entry_parser.py:14-16` 注释：「解析后编码，即 `int.from_bytes(DI4字节,'little')` 的 %08X」，如 `04FFAAF9`、`FF00DD01`。
- `test/test_dlt645_lme.py:90`：DI `04FFAAF9` 在帧内字节为 `bytes.fromhex("F9AAFF04")`（逆序）；`:128` DI `FF00DD01` 帧内为 `[0x01,0xDD,0x00,0xFF]`。

**组帧结论**：DI 字符串 `"04FFAAF9"`（高字节在前写法）→ 帧内字节 = `bytes.fromhex("04FFAAF9")[::-1]` = `F9 AA FF 04`。

## Caveats / 需查 PDF 的缺口

1. **控制码 5.2.3 位定义为图片**：md 无文本位定义表，本文位定义由应答控制码取值反推 + `dlt645_parser.py` 验证得出，逻辑自洽但**权威文本须查 `DLT645-2007 多功能电表通信协议.pdf` 5.2.3**。
2. **广播校时数据域线序**：文档正文（YYMMDDhhmmss）与帧格式表 `:804`（ss mm hh DD MM YY）表述不一致；且 `dlt645_parser.py:192-203` 把第 6 字节当「星期」而文档帧格式表写「YY 年」——**存在实现/文档差异**，组帧时须与用户确认第 6 字节语义（星期 vs 年）。
3. **表 A.1 读写属性**：json 未含，写数据 14H 组帧判断 DI 可写性时缺口。
4. 冻结/校时的广播地址（99H 全 9）与缩位地址（AA 全 A）已在文档确认，组帧可直接用。
