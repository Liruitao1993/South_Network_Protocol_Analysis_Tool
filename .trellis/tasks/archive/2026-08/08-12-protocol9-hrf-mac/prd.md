# PRD：协议9（通感一体化）无线信道单跳MAC帧解析

## 背景

协议9（新一代载波/通感一体化，`csg_new_gen_parser.py`）是双模协议：PLC 载波 + HRF 高速无线。工作区已有未提交的 HRF FC 可变区域解析（表42/45/46）+ GUI 通道下拉（索引9可见），但**无线信道的 MAC 帧层解析缺失**——版本2（单跳帧协议）帧会被按 12/32 字节 PLC 帧头错位解析。

## 需求

1. 无线信道（版本2 单跳帧协议）MAC 帧按 **表12 单跳MAC帧头（4字节）** 解析：
   - 帧头类型(1b) + 版本(2b) + 保留(5b)（字节0）
   - MSDU类型（字节1，**表13**：1=应用层报文 2=无线发现列表消息 128=IPV4报文）
   - MSDU长度（字节2-3，小端）
   - MSDU 载荷**无 VLAN+类型前缀**，直接按 MSDU 类型分派
   - 尾部完整性校验 CRC-32（同现有 MAC 帧）
2. MSDU类型=2（无线发现列表消息）按 **表139 MMeRF DiscoverNodeList** 解析：站点MAC地址(6B) + 统计序号(1B) + 信息单元 TLV 链（类型7bit+长度类型1bit / 长度1或2B / 内容）；信息单元类型0（站点属性）按表142 展开 14B 字段。
3. 所有 PLC 路径（版本1 标准帧协议 32B/12B 帧头）行为不变，回归测试全绿。

## 约束

- 仅改 `csg_new_gen_parser.py`（+ 测试文件）；GUI 通道下拉已存在（`main_gui.py` L587-605/1808），无需改动。
- 版本2 帧头类型位无意义（表5），不得依赖 header_type 决定长度。
- 多字节字段小端（AGENTS.md §9.7）。
- 解析结果 dict 键名遵循 §4.2（字段名/原始值/解析值/说明/偏移）。

## 验收标准

1. 输入版本2 单跳 MAC 帧（4B头 + 应用层报文 + CRC-32）→ 正确显示 帧头类型/版本/保留/MSDU类型(表13名称)/MSDU长度 + 应用层展开，无错位。
2. 输入完整无线 MPDU（`channel='hrf'`，HRF SOF FC + PB + 单跳MAC帧）→ 链路贯通：FC 可变区域（表45）+ PB + 单跳MAC头 + 应用层。
3. 输入无线发现列表消息（MSDU类型2）→ 显示 MAC/统计序号 + TLV 信息单元链，类型0 展开站点属性字段。
4. 版本1 帧（32B/12B）解析结果与改动前一致（test_csg_new_gen.py 全部通过）。
5. 新增测试用例覆盖 1/2/3，硬编码帧 + assert（项目 §7 惯例）。
