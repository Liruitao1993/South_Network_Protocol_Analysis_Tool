# 状态栏显示线程数并关闭时统一回收线程

## Goal

1. 主窗口状态栏实时显示当前应用存活的工作线程数量（鼠标悬停列出线程名），便于排查线程泄漏。
2. 关闭软件时统一、确定地停止/回收所有后台线程与定时器，不留残余线程，避免关闭途中后台任务弹窗或访问已销毁对象。

## Requirements

- 状态栏永久显示「线程: N」，N 为当前存活的非主线程数；每秒刷新一次。
- 悬停 tooltip 列出所有存活线程的名字（含主线程与 QThread/threading.Thread），方便定位。
- 关闭（真正退出，非最小化到托盘）时，按统一流程停止：串口、全局热键、剪贴板监听、TCP 抓包、Python 脚本执行线程、LLM 预处理线程、更新检查/下载线程，以及所有相关 QTimer。
- 阻塞型线程（网络 IO / 抓包）给有限等待，超时则断开信号放行，不强行 terminate（避免资源损坏）。
- 最小化到托盘路径不触发关闭回收（恢复后继续工作）。
- 不引入新第三方依赖（用标准库 `threading.enumerate()`，QThread 是其 Thread 子类，可被枚举）。

## Acceptance Criteria

- [ ] 启动后状态栏出现线程计数，数值随线程启停变化；tooltip 能看到线程名。
- [ ] 打开串口 / 开始 TCP 抓包时计数增加，关闭后计数回落。
- [ ] 关闭软件时无后台线程残留（任务管理器进程退出；控制台无线程相关异常 / RuntimeError）。
- [ ] 关闭途中不再弹更新检查对话框（与 `08-25-close-update-popup-guard` 协同）。
- [ ] 最小化到托盘后恢复，串口/抓包/定时器等仍正常。

## Non-Goals

- 不强制 terminate 阻塞在不可中断系统调用的线程（如 scapy 抓包）；通过其 stop 标志 + 有限等待回收，超时断开信号并随进程退出。
- 不改动 reflex_web / 打包内嵌 python 目录下的线程。
