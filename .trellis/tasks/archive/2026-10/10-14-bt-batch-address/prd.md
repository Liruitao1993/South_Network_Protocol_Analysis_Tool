# PRD：蓝牙工具 · 自定义按钮批量替换地址（按协议类别统一）

- 任务：`10-14-bt-batch-address`
- 版本：**1.23.83**（新功能）
- 用户原话：「蓝牙工具中的自定义按钮也需要支持批量替换地址的能力，通过按照协议类别统一进行替换」

## 1. 背景与问题

1.23.81 给每个自定义报文按钮加了可选的「协议 + 地址」绑定：点按钮发送时按该协议**替换地址域并重算校验**（`frame_addr_fix`）。
但**改地址只能一个个来**：「右键 → 编辑…」逐个改，或把按钮全导出改完再导入。

实际运维场景（换表位 / 换终端地址 / 换台区）是：**同一协议的一批按钮（几十个）同时换地址**，
现在的做法既慢又容易漏改（漏一个就有一帧发到旧地址）。

## 2. 目标

提供「**按协议类别一次性替换一批按钮的地址**」的能力：

- 选协议（南网 / 国网 / 645 / 698.45 / 依瓦 / 南网上行）→ 列出该协议的按钮 → 填一次地址 → 一次写入这批按钮。
- 写入的是**按钮自己的** `protocol` + `addr`（每按钮仍各自保存，不引入跨按钮的隐藏耦合）。
- 顺带支持**批量清除绑定**（把一批按钮的协议与地址一起去掉）。

## 3. 非目标（本次不做）

- 不做「协议共享一份地址模板」（用户明确选择「批量一次性写入」）。
- 不改发送时替换逻辑本身（`_apply_button_address` / `frame_addr_fix.apply` 语义不变）。
- 不做批量替换「报文内容」（只动地址参数；报文 hex 用既有的编辑/导入）。
- 不给右键单按钮菜单加同类入口（批量是全局操作，入口只在底部工具栏）。

## 4. 需求

### R1 入口与作用域

- R1.1 蓝牙页「自定义报文」底部的编辑工具栏新增一个按钮（暂定文案「批量地址…」），紧邻既有
  「批量新增…」；**工具栏与按钮区常驻行为不变**（1.23.82 的空间治理不回退）。
- R1.2 点击后弹出「批量替换地址」对话框，内容至少含：协议下拉 + 按钮列表（可勾选）+ 地址输入行
  （按所选协议动态生成）+ 预检摘要 + 确定/取消。
- R1.3 协议下拉的候选项来自 `frame_addr_fix.supported_choices()`（单一来源，界面不硬编码协议细节）；
  第一项为「（清除协议与地址）」= 批量解绑模式。
- R1.4 列表列出**全部**自定义按钮（含未绑定协议的），每行显示：名称 + 当前绑定摘要
  （如「南网 · 源=010203040506 · 目的=0」/「未绑定」）。
- R1.5 **默认勾选 = 已绑定所选协议的按钮**；另有「全选 / 全不选 / 只选本协议」三个快捷操作。

### R2 地址输入与校验

- R2.1 地址输入行按所选协议动态重建（字段名/提示/长度都取自 `frame_addr_fix`）。
- R2.2 输入后实时回显「将写入的字节」；能解析按钮报文时给出替换后预览（与单按钮编辑对话框同口径）。
- R2.3 校验按**每个按钮自己的报文**做（例如 698.45 的 SA 长度由该按钮帧的地址特征字节决定，
  不同按钮可以不同）——不得只用第一个按钮的报文校验。
- R2.4 选中协议但**一个地址都没填** → 点确定时拒绝并说明（与单按钮编辑对话框同口径）。
- R2.5 地址非法（长度不符 / 字符非法 / 与报文结构冲突）→ 该按钮判为**不可应用**，在列表里给出可读原因，
  且**默认不勾选**。

### R3 应用语义（明确、不静默）

- R3.1 点确定后：对**勾选且预检通过**的按钮写入 `protocol` + `addr`；其余按钮一个字节都不动。
- R3.2 若用户**手动勾上了预检失败**的按钮：二次确认（列出会跳过哪些、原因），确认后**跳过它们**继续；
  拒绝则完全不动。
- R3.3 若没有任何可应用的按钮 → 不改动任何按钮并提示。
- R3.4 应用后：日志给出汇总（协议名 + 按钮个数 + 地址摘要）与逐条失败原因；按钮 tooltip 立即反映新地址；
  配置立即落盘（重启后仍在）。
- R3.5 「（清除协议与地址）」模式下：勾选按钮的 `protocol` 与 `addr` 两键被移除，日志说明条数。

### R4 兼容与回归

- R4.1 旧配置（按钮无 `protocol`/`addr` 键）行为不变；**不新增配置键** ⇒ 不需要配置版本迁移。
- R4.2 单按钮编辑对话框（`ButtonEditDialog`）的既有行为与文案**逐字符不变**（只有内部实现改为调用共享函数）。
- R4.3 导出/导入 JSON 结构不变（`protocol`/`addr` 本来就在按钮字典里）。
- R4.4 工具栏加按钮后，**默认 / 14 / 16 号字下按钮文字不被裁**（判据 `width >= sizeHint`，见 AGENTS 陷阱 63）；
  极端字号若受页面最小宽度约束，需在 spec 里记录实测取舍。

## 5. 验收标准

1. 20 个南网按钮 + 3 个 645 按钮的列表：选「南网」→ 默认勾选 20 个 → 填源/目的地址 → 确定 →
   20 个按钮的 tooltip 与发送行为都变成新地址，3 个 645 按钮**逐字节未动**；配置落盘重启后仍生效。
2. 其中 1 个南网按钮的报文是坏 HEX → 该行显示原因、默认不勾；用户不勾它时点确定**直接成功**且不弹二次确认。
3. 勾上该坏按钮再点确定 → 二次确认列出它，确认后跳过它、其余照改；拒绝则所有按钮都不动（含地址未改的校验）。
4. 选「（清除协议与地址）」→ 确定 → 这 20 个按钮的 `protocol`/`addr` 被移除（导出 JSON 里看不到这两个键），
   发送时恢复「原样发送」（校验为 `worker.sent` 逐字节等于按钮内容）。
5. 单按钮编辑对话框的 96 项地址测试、蓝牙页 221 项既有测试全绿（行为零回归）。
6. `release_check.py --with-gui` PASS 数不降、无可归因于本任务的 FAIL（既有环境红除外）。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 地址校验只按一个按钮的帧做 → 部分按钮实际不可替换 | R2.3 逐按钮用自己的帧校验；预检把失败项默认排除 |
| 静默跳过失败项（用户以为全改好了） | R3.2 二次确认 + R3.4 日志逐条列出 |
| 工具栏加按钮导致按钮文字被裁（陷阱 63） | 实测 `width >= sizeHint`；必要时缩短文案 / 调整提示标签占宽 |
| 与 1.23.82 的空间治理互相干扰 | 空间治理的 [14] 段断言必须保持全绿 |
