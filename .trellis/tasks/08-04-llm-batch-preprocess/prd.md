# PRD: 批量解析 LLM 智能预处理

## 背景

当前批量解析流程：用户加载日志文件 → 硬编码规则剥离前缀 → hex 清洗 → 帧提取 → 解析器处理。

痛点：
- 实际日志文件格式极其复杂：混合多种协议帧、含 TCP/串口/调试前缀、时间戳格式不统一、中文注释穿插、数据分片/断帧
- 硬编码规则无法覆盖所有情况，每种新格式都需要改代码
- 无法从混合日志中按类型分类提取（如"只提取 TCP 报文"、"只提取上行帧"）
- 同一日志可能需要多次清洗才能得到可解析的帧

## 目标

在批量解析流程中植入 LLM API 调用接口，作为日志清洗/分类工作台。LLM 在现有内置解析逻辑**之前**运行，对原始日志进行智能预处理，产出可被软件继续处理的中间文件。中间文件可再次送入 LLM 做进一步清洗，最终交给软件内置解析器。

## 工作流

```
原始日志文件（任意格式）
  ↓ [加载到输入区]
  ↓ [LLM 预处理 1] ── prompt: "提取所有 TCP 相关的 hex 报文"
  ↓ 输出到中间文件（保存为 txt）
  ↓ [可选: 再次 LLM 预处理] ── prompt: "清理时间戳和前缀"
  ↓ 输出到清洗后文件
  ↓ [加载到批量解析输入区]
  ↓ [软件内置解析] ── 现有 parse_batch 流程
  ↓ 解析结果
```

## 需求

### 1. LLM API 配置
- 设置面板：API endpoint（默认 OpenAI 兼容）、API key、模型名称
- API key 存储在 config.json 明文（与现有串口配置同等安全级别）
- 支持自定义 endpoint（兼容 OpenAI 兼容 API：本地 Ollama、Azure、第三方）

### 2. 预处理工作区
- 批量解析页新增「LLM 预处理」面板区域
- 输入区：加载原始日志文件（或粘贴文本）
- Prompt 编辑区：用户编写预处理指令（内置常用模板下拉选择）
- 输出区：LLM 返回的预处理结果文本
- 操作按钮：「执行预处理」「保存输出到文件」「加载到批量解析」

### 3. LLM 调用
- 异步调用（QThread），不阻塞 GUI
- 调用时显示进度/状态
- 输出格式：LLM 返回纯文本，软件自动从中提取 hex 帧（方案 C）
- 自动分块：按行数分块发送（默认每块 200 行，用户可调），合并结果

### 4. 预处理管道
- 支持多轮预处理：第 1 次输出可作为第 2 次输入
- 每轮的 prompt 可不同
- 中间结果可保存为文件
- 最终结果可一键加载到批量解析输入区

### 5. Prompt 模板
- 内置常用模板（下拉选择）：
  - "提取所有 hex 报文帧"
  - "清理日志前缀，只保留 hex 数据"
  - "按协议类型分类提取"
  - "提取 TCP 报文"
  - "修复 hex 格式错误"
- 用户可自定义/保存模板

## 技术决策（已确认）

| 决策项 | 选择 | 理由 |
|---|---|---|
| 预处理位置 | 现有内置逻辑之前 | 原始日志太复杂，需先清洗 |
| 输出格式 | 纯文本 + 后处理 | LLM 负责清洗，软件负责提取帧 |
| API key 存储 | config.json 明文 | 本地桌面工具，与串口配置同等安全 |
| 大文件处理 | 自动按行数分块（默认 200 行/块） | 简单有效，prompt 要求每行独立处理 |

## 验收标准

- [ ] 设置面板可配置 LLM API（endpoint + key + model），测试连接成功
- [ ] 预处理面板：加载文件 → 编辑 prompt → 执行 → 查看结果
- [ ] 异步调用不阻塞 GUI，显示进度
- [ ] 大文件自动分块，合并结果
- [ ] 预处理结果可保存为文件
- [ ] 预处理结果可一键加载到批量解析输入区
- [ ] 支持多轮预处理（第 1 次输出 → 第 2 次输入）
- [ ] 内置 prompt 模板可用
- [ ] API 调用失败时显示错误，不影响现有功能
- [ ] 不使用 LLM 时，批量解析行为与现有完全一致

## 不在 MVP 范围

- 协议自动识别后自动切换解析器
- 流式输出
- 本地模型集成（MVP 只支持 OpenAI 兼容 API）
- 预处理结果持久化/历史记录
- 批量文件同时预处理（MVP 单文件）
