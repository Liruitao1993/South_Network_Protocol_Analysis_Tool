# PRD: 重写 0x0005 OFDMA多用户下发解析（通感一体新版）

## Goal

按《宽带双模通信模块（通感一体物联版）相关测试命令定义_增加相关接口.docx》中扩展ID=0x0005（OFDMA多用户下发）的定义，重写 `csg_new_gen_cmd_payloads.py` 中的 `_parse_test_ext_0005` 函数，修正当前因前置"扩展测试命令头"（国网新一代格式）导致的数据错位问题。

## Background

- 当前 `_parse_test_ext_0005` 假设数据域前3字节是"扩展测试命令头"（ng_mode / param1 / param2，国网新一代测试模式格式），之后才是OFDMA多用户下发内容。
- 通感一体物联版文档定义不同：扩展ID后直接就是OFDMA多用户下发数据，没有额外的3字节命令头。
- 文档字节编号起点：字节0 = 报文头长度（filelen 字段，即现有代码中的"文件长度"），字节1-2 = 扩展ID，字节3起 = 数据域。因此 Table 7 中的"字节3"就是数据域第1字节。
- 文档 Table 7：字节3位域定义 — OFDMA类型(bit0, 1bit) + OFDMA调度节点数(bit1-3, 3bit) + 保留(bit4-7, 4bit)。
- 文档 Table 8：每站点信息 — TEI(12bit, 跨字节3的8位 + 字节4的低4位) + 保留(4bit, 字节4的高4位)。
- 文档说明："目前OFDMA用例中只写了2个站点，当有3-4个站点时，可根据表中格式进行依次扩展。"

## Requirements

1. **移除前置3字节"扩展测试命令头"**：数据域第1字节直接按 Table 7 解析为 OFDMA 配置字节。
2. **Table 7 字节3位域解析**：
   - bit0: OFDMA类型 — 0=DL_OFDMA, 1=UL_OFDMA
   - bit1-3: OFDMA调度节点数
   - bit4-7: 保留
3. **Table 8 每站点 TEI 解析**：
   - TEI 共12位：低8位在第1字节，高4位在第2字节的低4位（小端式跨字节）
   - 第2字节高4位为保留
   - 站点数 = 调度节点数，依次循环解析
4. **剩余数据处理**：解析完所有站点后，剩余字节按"剩余数据"展示。

## Acceptance Criteria

- [x] 输入报文整帧解析到扩展ID=0x0005时：
  - OFDMA类型 = DL_OFDMA (0)
  - 调度节点数 = 1
  - 站点0 TEI = 0x0109（低字节0x09 + 高4位0x1）
  - 不再显示"扩展测试命令-新一代测试模式"、"TF符号数"、"FCH符号数"等国网格式字段
  - 不再显示帧类型/频段/eFC符号数/TF符号数/站点个数错位字段
- [x] 2站点及以上时，TEI按顺序依次解析，每站点2字节
- [x] 数据不足时给出明确的"数据不足"提示，不崩溃
- [x] 其他扩展ID（0x0001~0x0004, 0x0006~0x0008）解析不受影响

## Out of Scope

- 不修改其他扩展ID的解析逻辑
- 不修改测试帧外层结构（测试ID、保留、数据区长度、协议版本号、报文头长度、扩展ID读取）
- 不涉及国网新一代解析器（gw_new_gen_parser.py）
- 不新增测试帧命令或扩展ID

## Technical Notes

- 修改文件：`csg_new_gen_cmd_payloads.py` 中 `_parse_test_ext_0005` 函数
- 调用链：`_parse_cmd_test_frame` → `_parse_test_ext_payload` → `_parse_test_ext_0005`
- 数据入口 `data: bytes` 是去掉协议版本号、报文头长度、扩展ID之后的纯扩展数据（即文档中字节3起的内容）
