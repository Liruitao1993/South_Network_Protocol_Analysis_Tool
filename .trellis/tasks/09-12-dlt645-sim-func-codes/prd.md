# 645虚拟表从站功能码补齐（12H/16H/17H/18H/19H/1AH/1BH）

## Goal

645虚拟表当前只应答 11H 读数据 / 13H 读通信地址 / 15H 写通信地址 / 08H 广播校时，其余功能码一律回 `D1H` 异常（`dlt645_sim/engine.py:136`「暂不支持功能码」）。本任务把 DLT645-2007 §7 的其余常用功能码补上，让虚拟表能当"完整电表"被集中器/主站的初始化与运维流程走通。

## Confirmed Facts（代码证据）

- 引擎分派点：`dlt645_sim/engine.py:128-137`（13H/15H/08H/11H，其余 → `_error_response(..., func=func)`）。
- **组帧侧 schema 已有全部命令的字段模板**（可作数据域契约的唯一权威）：`dlt645_frame_schema.DLT645_CMD_SCHEMA`（`(REQ,0x12)` 读后续 / `0x14` 写数据 / `0x16` 冻结 / `0x17` 更改通信速率 / `0x18` 修改密码 / `0x19` 最大需量清零 / `0x1A` 电表清零 / `0x1B` 事件清零，含 `data_len` 与字段说明），`build_data()` 负责拼数据域。
- 数据域口径（已核实的实测结论，见 `dlt645_frame_schema.py:17-20`）：
  - 改密码 18H `L=0CH`（含 DI 前缀）
  - 最大需量清零 19H / 电表清零 1AH `L=08H`（PA+P0P1P2+C0~C3，**无 DI**）
  - 事件清零 1BH `L=0CH`（密码组 4 + 操作者 4 + 事件标识 4）
  - 冻结 16H `L=04H`（线序 mm hh DD MM）；更改速率 17H `L=01H`
- 应答形态：除 11H/12H 带数据外，其余正常应答 `L=00H`（`_EMPTY_RSP_FUNCS`，`dlt645_frame_schema.py:219`）。
- 现有测试：`test/test_dlt645_sim.py`（引擎既有功能码）、`test/test_dlt645_sim_event_word.py`（63+ 项，含事件状态字）、`test/test_dlt645_sim_lme_query.py`（95 项）。

## Requirements

### R1 逐功能码实现（按 §7 文档）
| 功能码 | 行为 |
|---|---|
| 12H 读后续数据 | 按附加数据/后续帧返回该 DI 的剩余数据（虚拟表可按档案一次性给完 + 声明"无后续"） |
| 16H 冻结 | 正常应答 `L=00H`；可选把冻结时标写入档案（如冻结时间项） |
| 17H 更改通信速率 | 正常应答 `L=00H`；可选把速率特征字记入日志（**不真改串口波特率**，避免自断连接） |
| 18H 修改密码 | 校验原密码（默认 000000）；成功应答 `L=00H`；失败 → `D8H` + ERR bit2（密码错） |
| 19H 最大需量清零 | 需量类 DI 归零（档案里 `0011xxxx` 等），应答 `L=00H` |
| 1AH 电表清零 | 电能量/需量/冻结归零（**保留电表清零事件记录，§7.10 注**），应答 `L=00H` |
| 1BH 事件清零 | 按事件标识清零（FFFFFFFF=全部），应答 `L=00H` |
- 每项都要有"数据域长度/格式非法 → `DnH` 异常 + ERR 位"的分支，不能崩。

### R2 档案/状态联动
- 19H/1AH/1BH 清零后，档案内存值与「档案数据」页表格同步（GUI 侧刷新），并发 `archive` 持久化（沿用 `_archive_save_quiet`）。
- 清零/改密码等写类操作在收发日志给出可读标注（如「19H 最大需量清零：需量项已归零」）。

### R3 保持既有行为
- 11H/13H/15H/08H 与未知 DI 的异常应答行为不变（既有测试不得回归）。
- 引擎仍保持"纯逻辑无 Qt"，不引入 GUI 依赖。

### R4 测试
- 新增 `test/test_dlt645_sim_func_codes.py`：
  - 逐功能码：用 `DLT645FrameGenerator.generate_frame((REQ, 0xNN), {...})` 组请求（**复用 schema 契约，不手写字节**）→ 引擎应答 → `L`/控制码/ERR 断言 → `DLT645Parser` 回读断言。
  - 密码错分支（18H 原密码错 → D8H + ERR bit2）、长度非法分支、清零后档案值断言。
  - 可选串口回环（COM1↔COM2 存在时）：16H/1AH 端到端。
- 沙箱化 `app_paths.data_path`，不写用户 `dlt645_sim_data.json`。
- `python release_check.py` 保持全绿（基线 PASS=48 FAIL=0 WARN=0）。

## Acceptance Criteria

1. 12H/16H/17H/18H/19H/1AH/1BH 七个功能码都有合规应答（正常 `L=00H` 或带数据），不再回「暂不支持功能码」。
2. 18H 密码错 → `D8H` + ERR bit2；长度/格式非法 → 对应 `DnH`，均不崩。
3. 19H/1AH/1BH 后档案中相关 DI 已归零，且「档案数据」页表格同步、`dlt645_sim_data.json` 落盘。
4. 11H/13H/15H/08H 与既有 DI 行为零回归（`test_dlt645_sim.py` 等既有测试全过）。
5. 新测试脚本全过；`release_check.py` 无 FAIL/WARN。

## Out of Scope

- 不做 14H 写数据（写单点 DI）——涉及"哪些 DI 可写"的白名单设计，另开。
- 不真改串口波特率（17H 只应答并记日志）。
- 不做冻结曲线/负荷记录的数据块生成（曲线类 DI 仍按档案单值返回）。
- 不改 `dlt645_frame_schema.py` / `dlt645_frame_gen.py` / `dlt645_parser.py`（只复用）。

## Risks / Deferred

- 12H 读后续数据的"后续"语义在虚拟表里天然无分页：实现为"一次性给完 + 声明无后续帧"，需在 PRD 评审时确认该口径可接受。
- 1AH 电表清零的范围（哪些 DI 算电能量/需量/冻结）需按档案里的 DI 前缀明确定义，避免误清用户手填的自定义 DI。
- 写类功能码会真改内存档案（并落盘），测试必须沙箱化；GUI 冒烟时注意不要用用户档案。
