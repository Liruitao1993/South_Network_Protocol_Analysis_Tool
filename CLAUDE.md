# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A multi-protocol power utility communication frame parser with PySide6 GUI. Supports Southern Grid (CSG), State Grid (GDW), PLC RF, HDLC/DLMS, DLMS Wrapper/APDU, and DLT645-2007 protocols.

## Running the Project

```bash
# Install dependencies
pip install pyside6

# Run GUI (main entry point)
python main_gui.py

# Run web version (requires streamlit)
streamlit run streamlit_app.py

# Build executable
pyinstaller 协议解析工具.spec        # Full version (includes GDW custom AFN)
pyinstaller 南网协议解析工具.spec      # Southern Grid only
```

## Architecture

### Entry Point
- `main_gui.py` — PySide6 GUI application (~2850 lines). `MainWindow` class (~2500 lines) is the monolithic main window. New UI components should be extracted to standalone files (like `frame_gen_widget.py`) and imported here.

### Parsers (Independent, each returns nested dicts)
All parsers return nested dicts with standard keys: `原始值`/`原始字节`, `十进制`/`解析值`, `说明`/`名称`/`业务说明`.

| File | Class | Protocol |
|------|-------|----------|
| `protocol_parser.py` | `ProtocolFrameParser` | Southern Grid (Q/CSG1209021-2019) |
| `gdw10376_parser.py` | `GDW10376Parser` | State Grid (Q/GDW 10376.2—2024) |
| `plc_rf_parser.py` | `PLCRFProtocolParser` | PLC RF (万胜海外 V1_04) |
| `hdlc_parser.py` | `HDLCParser` | HDLC/DLMS (IEC 62056-46) |
| `dlms_deep_parser.py` | `DLMSDeepParser` | DLMS APDU deep parse |
| `dlt645_parser.py` | `DLT645Parser` | DLT645-2007 |

### Supporting Modules
- `protocol_tool.py` — `ControlField` (ctypes struct) and `Frame` dataclass for Southern Grid frame packing.
- `gdw10376_tool.py` — State Grid control field + constants.
- `send_frame_lib.py` / `gdw_send_frame_lib.py` — Frame generators for Southern/State Grid.
- `frame_generator_schema.py` / `gdw_frame_generator_schema.py` — Schema definitions for frame generation UI.
- `serial_worker.py` — Serial communication thread (`SerialWorker`).

### Lookup Modules
- `obis_lookup.py` — OBIS code lookup (HDLC/DLMS).
- `command_lookup.py` — PLC RF command lookup.
- `dlt645_di_lookup.py` — DLT645 DI lookup.
- `gdw_afn_lookup.py` — State Grid AFN lookup.

### Data Files (Runtime Read/Write)
- `custom_di.json` — Southern Grid custom DI entries (GUI adds/removes at runtime).
- `gdw_custom_afn.json` — State Grid custom AFN+Fn entries.
- `dlt645_di.json` — Generated by `generate_dlt645_di.py`; do not edit manually.
- `config.json` — Serial port configuration.

## Byte Order Rules

- **Southern/State Grid protocols**: Length field and DI use **little-endian**.
- **HDLC/DLMS**: Network byte order (big-endian).
- **DLT645**: BCD encoding, address field low-byte first.

## Testing

No formal test framework. Test scripts are standalone:

```bash
python test_dlms.py
python test_hdlc.py
python test_plc_rf.py
python test_ber_tlv.py
python test_actual_hdlc.py
python test_special_frame.py

```

Each contains hardcoded test frames with assertions or print-based verification.

## Critical Traps

- **`main_gui.py` `_clear_layout`** recursively destroys all child widgets. Any query tab logic modification must account for this or widgets will leak/crash.
- **`current_protocol` index** (0=Southern Grid, 1=PLC RF, 2=HDLC, 3=Wrapper, 4=APDU, 5=DLT645, 6=State Grid) is hardcoded. Adding a new protocol requires updating `_on_protocol_changed`, `_update_protocol_lookup_tab`, and `_extract_frames_for_protocol`.
- **DLMS deep parse** is triggered by **double-clicking** the `DLMS APDU` row in the table, not automatic.
- **HDLC byte stuffing**: `7E` inside a frame becomes `7E 5D`; `7D` becomes `7D 5D`. Parser handles this automatically; frame generation must also handle it.
- **Frame generation / preset tabs** are only visible for Southern Grid (0) and State Grid (6) protocols, controlled by `setTabVisible`.
- **PyInstaller spec files**: `协议解析工具.spec` bundles `custom_di.json`, `dlt645_di.json`, and `gdw_custom_afn.json`; `南网协议解析工具.spec` only bundles the first two.

## 协议文档的参考

- 南网解析器所使用的参考文档为，“PLUZ计量自动化系统技术规范.md”，在遇到解析问题是，应当查看该文档进行检索找到正确的解析和正确的协议定义。针对南网解析器，对于详细版本信息的信息条目定义参考文档为“LME产品相关信息生产运维接口手册_V2.4_251115.md”。同样的在遇到解析问题时应当检索该文档了解协议的详细定义。

- 国网解析器所使用的参考文档为，“集中器本地通信模块接口-2024.md”，这个文档是国网本地接口协议解析器对应的协议文档，如果遇到协议问题，需要严格参考该文档的定义来进行解析处理。
- 645协议解析器，参考的文档为，“DLT645-2007.md”和“国网计量中心电能表全性能试验检测公告-第4号补遗-事件记录采集-远程费控功能和负荷曲线抄读功能.pdf”，你应该能够处理pdf文件，如果遇到需要查看协议文档的时候并且协议文档是PDF的时候，你可以调用pdf相关的skill来进行检索。
- 关于HDLC解析器的参考文档为，“HDLC.md”和“HDLC解析说明.md”和“IEC 62056-46.PDF”。
- 关于DLMS解析器的参考文档为，“DLMS_Protocol.md”和“DLMS_Protocol.pdf”。
- 关于万胜协议解析器的参考文档为，“4.md”。
