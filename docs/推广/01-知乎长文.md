## 正文

先说结论：**大部分现场"报文有问题"，其实帧是对的，是校验范围理解错了。**

下面这条 698.45 读取请求，我在三个不同的台体上见过同一个误判：

```
68 13 00 43 01 00 01 17 64 2C 05 01 60 20 0F 02 00 00 AD 8B 16
```

### 一、这条帧到底在干什么

按 DL/T 698.45 的链路层拆：

| 字段 | 原始值 | 含义 |
| --- | --- | --- |
| 起始字符 | `0x68` | 帧起始标志 |
| 长度域 | `1300` | 低 14 位 = 19，单位字节 |
| 控制域 | `0x43` | DIR=0（客户机→服务器）、PRM=1（客户机发起）、分帧=0、扰码=0、功能码=3（用户数据） |
| 地址特征 | `0x01` | 长度=2、逻辑地址 0、单地址 |
| 服务器地址 SA | `0001` | 2 字节 |
| 客户机地址 CA | `0x17` | 23 |
| 帧头校验 HCS | `0x2C64` | CRC-16 |
| APDU | `05 01 60 20 0F 02 00 00` | GET-Request，PIID=0x60，OAD=200F0200 |
| 帧校验 FCS | `0x8BAD` | CRC-16 |
| 结束字符 | `0x16` | 帧结束标志 |

关键是 OAD = `20 0F 02 00`：

- OI = `0x200F` → **电网频率**（数据变量类）
- 属性 2 → 数值
- 元素 0 → 全部内容

所以这帧在说：**"把电网频率的当前值给我。"**

> 一个把「OI + 属性 + 元素」翻译成人话的解析器，和只输出 `200F0200` 的解析器，
> 在现场的差别是「要不要再翻一次文档」。

### 二、为什么很多人会判错校验

常见的三个坑：

**1. HCS 和 FCS 的覆盖范围不一样。**
HCS 只覆盖「长度域 + 控制域 + 地址域 + HCS 自身之前」；FCS 覆盖「长度域到链路用户数据」。拿着整帧去算 CRC，必然对不上。

**2. 长度域的低 14 位才是长度。**
`1300` 直接当 `0x1300 = 4864` 会得到荒谬的长度；取低 14 位才是 19。高 2 位是保留位。

**3. 台体日志里的 HCS / FCS 经常是空的。**
这一点最坑：模拟器/台体吐出来的帧，HCS、FCS、PBCS、ICV 这些由**硬件发射机在发射时填充**的字段，常常是 `00 00` 或全 0。
于是你会看到「解析全对，但校验失败」——其实它根本还没被填。

**所以正确的判定是「未填充」，而不是「校验失败」。** 这两句话对现场的意义完全不同：前者是"等设备发"，后者是"帧做错了"。我曾经因为混淆这两者，在一个台体上白排查了半天。

### 三、这件事为什么值得做成工具

我原来的流程是：

1. 从串口日志里复制一段 hex
2. 打开协议 PDF，Ctrl+F 找字段表
3. 一个字节一个字节地对偏移
4. 拿计算器敲 CRC
5. 发现差一位，回到第 2 步

一条帧 10 分钟，一天几十条。**问题不在难，在重复。**

后来我把它做成了一个 Windows 桌面工具，现在这条帧的流程是：

1. 粘进去
2. 回车

得到的是上面那张逐字段表，并且：

- 点任意解析行，输入框里对应的**字节会反向高亮** —— 不用再数第几个字节
- HCS、FCS 各给一个结论：**通过 / 失败 / 未填充**
- OAD 直接翻译成「电网频率 · 数值 · 全部内容」

> 【替换】这里可以插一句你自己最常用的场景，比如「我一般拿它先看长度域，一眼就能判断是不是分包没拼全」。

### 四、不止一种协议

现场不会只遇到一种协议。这个工具现在覆盖 15 种，我常用的几种：

- **DL/T 698.45**（含 A-XDR 数据解码）
- **DL/T 645-2007**（BCD 编码、地址域低字节在前）
- **南网 / 国网 Q/GDW 10376**
- **DLMS / HDLC**（IEC 62056-46，CRC-16/FCS）
- **新一代载波、国网双模、HDC 1.0**

同一个窗口里还能做：批量解析日志（自动从混杂文本里提帧、导出 Excel）、组帧、串口 / 蓝牙收发、通信时序图、报文对比。

**它不是一个"协议库"，是一个现场调试台。** 这两者的区别是：前者要你会写代码，后者双击就能用。
