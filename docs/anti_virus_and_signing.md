# exe 被杀软/SmartScreen 拦截：成因与处置

> 结论先说：**装机量越小的国产小工具，越会被「无签名 + 每次哈希都变」判定为可疑**。
> 这不是代码有病毒，而是「发布方式」的问题。下面按**有效性排序**给方案，
> 并明确哪些只能解决「你自己的电脑」、哪些才能解决「别人下载时」的问题。

---

## 一、先分清是哪种拦截（否则改错方向）

| 现象 | 谁在拦 | 本质 | 处置见 |
| --- | --- | --- | --- |
| 双击刚编出来的 exe 就被删/隔离，日志里有 `Trojan:Win32/Wacatac.B!ml` 之类 | Defender 实时防护 | 启发式误报（PyInstaller 引导器 + 未签名 + 低信誉） | §二、§四 |
| 360 弹「发现木马/风险程序」，或直接拦截运行 | 360 云查杀 | 无签名、无软件白名单记录、启发式 | §二、§四 |
| 下载后第一次运行弹「Windows 已保护你的电脑」（蓝色全屏） | SmartScreen | 文件带 **Mark-of-the-Web** + 无签名 + 无下载信誉 | §三 |
| 装完能跑，但每次更新又被拦 | 综合 | **文件名带时间戳 ⇒ 哈希/文件名每次都新 ⇒ 云信誉永远从零** | §二.3、§三 |

> 判定小技巧：右键 exe → 属性，底部若有「解除锁定」勾选框，说明文件带 MOTW（来自网络），
> 此时"保护你的电脑"是 SmartScreen 的信誉问题，不是你本机杀软。

## 二、构建侧：把「像恶意软件的特征」降到最低（本机可做，立即见效）

本仓库已经落地的：

1. **不用 UPX**（`upx=False`，两份 spec 都写死）。压缩壳与恶意软件同构，是启发式的头号特征。
2. **版本资源写全**：`CompanyName` / `ProductName` / `FileDescription` / `FileVersion` /
   `OriginalFilename` / `LegalCopyright`。缺 `OriginalFilename`/`CompanyName` 会明显拉高评分。
3. **应用清单带 `assemblyIdentity`**（"谁家的什么软件什么版本"），且不申请提权（`asInvoker`）。
   > ⚠ 清单必须是**完整**清单：PyInstaller 的 `create_application_manifest()` 是整份替换，
   > 只传 `assemblyIdentity` 会把 `supportedOS` 与 `longPathAware` 一起冲掉。
4. **两种发布形态都在**：
   - `南网协议解析工具.spec` → 单文件 exe（便携）
   - `协议解析工具_onedir.spec` → 文件夹形态（**推荐对外分发**）
5. **onedir 优先**：单文件 exe 每次运行都要解到 `%TEMP%\_MEIxxxxxx` 再执行 —— 与
   "释放器"行为同构，且启动慢 2~5 秒。文件夹形态没有自解压动作，被拦概率显著更低、
   启动更快、内存更稳。

构建命令：

```powershell
# 文件夹形态（安装包用它；产物 dist\协议解析工具\协议解析工具.exe）
pyinstaller 协议解析工具_onedir.spec --noconfirm
dist\协议解析工具\协议解析工具.exe --self-test      # 返回码 0 = 打包合格

# 单文件便携版（Release 附件用）
pyinstaller 南网协议解析工具.spec --noconfirm
```

> 两份 spec 的版本资源 / 清单 / 依赖清单都在 **`pyinstaller_meta.py`**（单一来源），
> 改一处两边同时生效 —— 不要再往 spec 里各写一份。

### 2.3 关于「文件名带时间戳」

`..._v1.23.93_20261022120000.exe` 这种命名对**人**友好（区分多次编译），但对**云信誉**
是灾难：每个文件都是新哈希 + 新文件名，SmartScreen/360 的"见过很多次 ⇒ 放行"永远积累不起来。

对外发布时建议：**固定文件名**（如 `Setup_ProtocolAnalyzer_v1.23.93.exe`），
版本号写在文件名里而不是时间戳；内部构建再保留时间戳。

## 三、分发侧：唯一能真正消除「未知发布者 / 已保护你的电脑」的办法

**代码签名**。没有第二条路 —— 元数据、清单、换打包器都只是降低概率。

| 方案 | 效果 | 成本/门槛 | 说明 |
| --- | --- | --- | --- |
| **EV 代码签名证书**（U 盾/云 HSM） | SmartScreen **立即**信任 | 年费较高，需企业资质 + 硬件令牌 | 对新发布者最有效；私钥不可导出（2023 起 CA/B 强制） |
| **OV 代码签名证书** | 先仍提示，**随下载量积累**才转信任 | 年费中档，同样需企业资质 + HSM | 便宜些，但"刚发布那几周"仍会被拦 |
| **Azure Trusted Signing**（微软云签名） | 同 OV/EV（按账户验证等级） | 订阅费低，但要求**可核验的经营主体与年限**、且对个人账户限制多 | 适合有正规公司主体的团队；开通前先确认资格 |
| **自签名证书** | **只对"手工信任过该证书"的电脑有效** | 免费 | 适合**内部几台机器**；对外分发毫无作用，别指望它过 SmartScreen |

内部署（同事/现场几台机器）的可行做法：

1. 生成自签名代码签名证书（`New-SelfSignedCertificate -Type CodeSigningCert`）；
2. 导入到目标机「受信任根证书颁发机构」；
3. 用 `signtool sign /a /fd sha256 /tr <时间戳服务器> /td sha256 <exe>` 签名。
   → 目标机不再报"未知发布者"，但**未导入证书的机器仍然会报**。

> 时间戳（`/tr`）一定要加：否则证书到期后，已签名的旧版本会全部失效。

### 3.1 购买/申请前的核对清单

- 证书类型是 **Code Signing**（不是 SSL/TLS）；
- 支持 **SHA-256 + RFC3161 时间戳**；
- 交付形态是 **硬件令牌或云 HSM**（现在的 CA 不再给可导出私钥的 .pfx）；
- 签名主体名称与安装包「发布者」一致（不一致会被当作"套牌"）。

## 四、误报申诉（免费，值得做；但别指望立竿见影）

1. **微软 Defender 误报**：
   <https://www.microsoft.com/en-us/wdsi/filesubmission>
   选「Software developer」→ 上传 exe → 说明是自研工具、附官网/仓库地址。
   通常 1~3 个工作日；通过后**同一哈希**不再报，但**重新编译换了哈希仍可能再报**。
2. **360 误报/白名单**：360 开放平台「文件申诉 / 软件收录」入口提交；
   企业可申请加入软件白名单（需营业执照等）。
3. **多引擎自查**：先传 VirusTotal 看是哪几家在报，申诉时把"仅 N/70 报毒"作为证据。
   > 注意：VirusTotal 上传即公开样本，商业软件上传前确认可接受。

4. **发布页写清楚**：给出 SHA256、源码仓库、构建方式（本项目 README 已写"可自行从源码打包"），
   能显著降低用户与安全软件的敌意。

## 五、只解决「我自己的电脑」（开发机）

构建/自测时被实时防护打断很烦，本仓库提供**最小范围**放行脚本：

```powershell
python scripts\defender_exclude_build.py --show     # 看当前排除项
python scripts\defender_exclude_build.py --add      # 需管理员：只加 dist\ 与 build\
python scripts\defender_exclude_build.py --remove   # 撤销
```

它**只**调用 `Add-MpPreference -ExclusionPath` 放行本仓库的两个产物目录，
不关实时防护、不改注册表、不整盘放行。

360 的对应操作（图形界面）：`防护中心 → 信任与拦截 → 信任区 → 添加目录`，
只加 `dist\`。**不要**加整个项目目录。

> 这两条只影响你自己的机器。对外分发被拦，仍然要靠 §三。

## 六、稳定性清单（"编译后非常稳定"）

| 项 | 做法 | 原因 |
| --- | --- | --- |
| 构建时不被打断 | 把 `build\`、`dist\` 加进实时防护排除（§五），构建期间别让杀软扫 | 杀软中途锁/删临时 DLL 会造成**产物缺文件**，表现为随机崩溃 |
| 用 onedir 对外 | 见 §二.5 | 无自解压、启动快、依赖文件可被系统缓存 |
| 打包后必跑自检 | `协议解析工具.exe --self-test` 返回 0 | 不建窗、不读写配置，能发现缺 hiddenimports |
| 固定 Python/PyInstaller 版本 | 记录 `python --version`、`pyinstaller --version` | 升级工具链后 `_internal` 布局与 hook 会变，需重跑自检 |
| 不混用 32/64 位 | 全程 64 位 | 混用会在客户机报 `%1 不是有效的 Win32 应用程序` |
| 数据文件与 exe 分离 | 配置写在 `app_paths.data_path()`，不写安装目录 | 装到 `Program Files` 时目录只读，写盘会失败（本仓库已如此） |
| 路径含中文 | 已支持；但**建议安装目录用 ASCII** | 少数老设备驱动/命令行工具对非 ASCII 路径处理不好 |
| 卸载残留 | Inno Setup `UninstallDisplayIcon` + 数据目录独立 | 升级覆盖安装不丢配置 |

## 七、给本项目的推荐组合（性价比最高）

1. **对外分发**：`协议解析工具_onedir.spec` 构建 → Inno Setup 打成安装包 →
   （有条件则）**OV/EV 证书签名** → 上传 Release，并在发布页给 SHA256。
2. **无证书阶段的兜底**：安装包 + 固定文件名 + 发布页说明 + 向微软/360 各提交一次误报。
3. **本机开发**：`scripts\defender_exclude_build.py --add`，360 手工加 `dist\` 到信任区。
4. **验收**：每次发版跑 `pyinstaller ... && exe --self-test`，再 `python release_check.py`。

> 最后一句实话：**不签名的 exe，无论怎么打包，都不可能稳定通过 SmartScreen 与 360 云查杀。**
> 能做的只是把误报概率压到最低、并让"愿意信任你的人"能顺利放行。
