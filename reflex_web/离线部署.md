# Reflex Web 离线部署

## 两种部署方式

### 方式一：内嵌 Python（推荐，零安装）

目标机器无需安装 Python，解压即用。适合分发给没有 Python 环境的用户。

**构建（有网机器）：**

```powershell
python reflex_web\build_embedded_deploy.py --python-version 3.12
```

**部署（无网目标服务器）：**

1. 把 `dist\reflex_web_embedded` 整个目录复制到目标服务器
2. 运行 `start_web.cmd`（Windows）或 `./start_web.sh`（Linux）
3. 浏览器访问 `http://服务器IP:8080`

**优点：** 目标机器零安装，复制即用
**限制：** Windows 版只能在 Windows 上运行，Linux 版只能在 Linux 上运行

---

### 方式二：UV 虚拟环境（需要目标机器有 Python）

目标机器需要安装相同版本的 Python，但不需要联网安装依赖。适合已有 Python 环境的服务器。

**构建（有网机器，需安装 UV）：**

```powershell
python reflex_web\build_offline_deploy.py --python-version 3.12
```

**部署（无网目标服务器）：**

1. 把 `dist\reflex_web_offline` 整个目录复制到目标服务器
2. 确保目标服务器已安装 Python 3.12（或对应版本）
3. 运行 `start_web.cmd`（Windows）或 `./start_web.sh`（Linux）
4. 浏览器访问 `http://服务器IP:8080`

**优点：** 体积更小，与系统 Python 共享
**限制：** 目标机器需要安装对应版本的 Python

---

## 运行数据目录（**重要**，升级不丢数据的关键）

运行时会写盘的数据**不在部署目录内**，默认放在**部署目录的上一级**：

```text
<某目录>/
├── reflex_web_embedded/          # 或 reflex_web_offline/ —— 部署目录，升级时整体替换
│   ├── reflex_web/               # 代码（不含任何运行数据）
│   ├── 迁移数据.cmd / .sh         # 旧版本数据搬迁辅助（见下）
│   └── start_web.cmd / .sh
└── nw_web_data/                  # ← 运行数据（升级不受影响）
    ├── data/
    │   ├── feedback.db           # 问题反馈库（SQLite）
    │   ├── frameshare.db         # 报文分享库（SQLite）
    │   └── uploads/feedback/     # 反馈截图
    ├── downloads/                # 「发布管理」上传的客户端 exe / version.json / archive
    └── admin_config.json         # 管理员口令哈希
```

- 由启动脚本注入环境变量 `NW_WEB_DATA_DIR` 指向该目录；**启动脚本已设则不覆盖**，可自行指到别的盘：

  ```powershell
  set NW_WEB_DATA_DIR=D:\nw_web_data
  start_web.cmd
  ```

- **升级**：把部署目录整体替换即可，`nw_web_data/` 在部署目录之外，不受影响；备份只需拷这一个目录。
- **随包静态资源 vs 运行时产物**（同在一个 `downloads/` 目录里，但来源不同）：
  - `client_screenshot.png`（首页 Hero / 下载页截图）与 `client_readme.md`（客户端说明）**随部署包走**（在部署目录的 `reflex_web/downloads/` 内），程序**优先读数据目录、缺失时回落**到随包资源 —— 所以新部署也能直接看到截图与说明，运维也可把新图放进数据目录覆盖；
  - `*.exe`、`version.json`、`archive/` 属**运行时产物**（由「发布管理」写入数据目录），**不进部署包**。新部署的「客户端下载」Tab 会显示「客户端 exe 未就绪」，用管理员登录后上传一版即可。
- 启动日志会打印实际生效的数据目录路径，可用它核对是否落在预期位置。
- 注意：**直接运行** `python reflex_web/run_app.py`（不带启动脚本、也没设变量）时，数据会回落到仓库内的 `reflex_web/data/`（开发态行为）。生产请用启动脚本，或自行设置 `NW_WEB_DATA_DIR`。

### 从旧版本升级（1.23.15 之前部署的）

旧版本把数据写在**部署目录内**（`<部署>/reflex_web/data/`、`downloads/`、`admin_config.json`）。首次升级只需把旧数据搬出来一次：

1. 用**旧的**部署目录里的 `迁移数据.cmd`（或产物中新的 `迁移数据.cmd`）——它会读当前目录、把旧位置的数据拷进 `nw_web_data/`：

   ```powershell
   cd <旧部署目录>
   .\迁移数据.cmd        # 或 Linux: ./迁移数据.sh
   ```

   也可以手工拷贝：把旧部署目录下 `reflex_web\data\`、`reflex_web\downloads\`、`reflex_web\admin_config.json`
   拷进 `<旧部署目录的上一级>\nw_web_data\` 的对应位置（`data\`、`downloads\`、`admin_config.json`）。

2. 再替换部署目录为新版本，启动。

> ⚠️ **不要先删旧部署目录**：那样旧数据会一起被删。若已经删了，只能从备份恢复（见下）。
> 若旧目录仍在、且新版本启动时数据根还是空的，程序会在启动时**自动搬移**一次（日志会列出搬了什么），此时第 1 步可省略。

### 备份与恢复

- 备份：停服后整体拷贝 `nw_web_data/` 即可。
- 恢复：把备份内容放回 `nw_web_data/`（或 `NW_WEB_DATA_DIR` 指定的目录）后启动。

## 通用说明

### 修改端口

```powershell
start_web.cmd --port 9000
```

**固化默认端口**（目标服务器只开放某个端口时用；会写进启动脚本，双击即用该端口）：

```powershell
python reflex_web\build_embedded_deploy.py --skip-deps --port 8091
```

> Windows 局域网服务器从零到上线的完整步骤（防火墙放行、开机自启、备份、升级、排错）见
> **`docs/Web版局域网部署教程.md`**。

### 注意事项

- `.venv` 或内嵌 Python 只能在**相同操作系统**、**相同 CPU 架构**之间复制
- `reflex_web/.web` 是前端构建产物，必须包含在部署目录中
- 目标服务器不需要 Node.js
- Reflex Web 版支持协议 0-10（11 种），HDC 1.0（索引 11）仅在 PySide6 主程序支持

### 反馈与分享数据的来源

GUI 桌面客户端的问题反馈通过 `POST /api/feedback` 提交（1.20.0 起），写入同一个 `nw_web_data/data/feedback.db`；部署后把 GUI 反馈对话框里的服务器地址改为本服务器地址即可（如 `http://服务器IP:8080`）。
网页「报文分享」与 GUI 的「分享此帧」共用 `nw_web_data/data/frameshare.db`。

### 前端编译

如果部署目录中没有 `.web/build/client`，需要先编译前端：

```powershell
cd reflex_web
reflex export --frontend-only --env prod --no-zip
```

### PyInstaller EXE 打包（可选）

也可以打包为单文件 EXE（但体积较大，启动较慢）：

```powershell
cd reflex_web
pyinstaller reflex_web_exe.spec --clean
```

输出：`dist/协议解析工具Web版.exe`

exe 单文件运行时的数据目录为 **exe 同级** 的 `nw_web_data/`（单文件 exe 的解包临时目录退出即删，不能用来存数据）；升级只需替换 exe 文件，数据不受影响。同样可用 `NW_WEB_DATA_DIR` 指定到别处。
